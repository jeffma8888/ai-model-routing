## 1. Problem
- A product or pipeline makes the same kind of model call many times: triage a support ticket, extract invoice fields, write a unit test, grade an answer against a rubric. Each such kind of call is a **task**: a repeated call with an **acceptance check** that says whether one output is right (agreement with a gold label, exact match on extracted fields, generated tests passing, a rubric pass)
- Sending every call of a task to the strongest model wastes money; sending it to the cheapest model silently lowers quality, and nothing in the logs says so
- The fix is to route per task: measure each candidate model's **success rate** against the task's acceptance check on a calibration set, and pick the cheapest model whose measured rate clears the task's bar with statistical confidence, with fallback when a call fails, a log of every attempt, and cost rolled up by any tag
- Judge and eval calls are the first-class use case, because a wrong judge corrupts every decision downstream of it and because a judge must not grade its own family's output (generator isolation, 5.2). Nothing in the routing rules is specific to judging: the library has no notion of a domain beyond a task name, its bar and its acceptance counts

## 2. Two flavors, one algorithm
- `cost_effective`: among models that clear the bar, pick the one with the lowest expected cost per call; ties go to higher quality
- `cost_blind`: identical pipeline, but the router treats token cost as 0, so among models that clear the bar it picks the highest quality. Fallback, monitoring and attribution are unchanged; the log still records list-price cost so spend stays visible
- The flavor changes exactly one thing: the `routing_cost` used to rank candidates

## 4. Data model

### 4.1 Model and Registry (`registry.py`)
- `@dataclass(frozen=True) class Model`: `id: str`, `family: str`, `price_in: float` (USD per 1M input tokens), `price_out: float` (USD per 1M output tokens), `context_window: int`, `aliases: dict[str, str]` (default empty; provider name to that provider's model ID), and from v1.15 `price_valid_until: str | None` (default `None`)
- v1.15 `price_valid_until` is the last day, inclusive, on which the vendor states the list price, as an ISO date string `YYYY-MM-DD` (four, two and two ASCII digits joined by hyphens, naming a day that exists). Any other value, including a `datetime.date` object, another date spelling or an impossible day such as `2026-02-30`, raises `ValueError` at construction. It is kept as a string so `dataclasses.asdict(model)` stays JSON-able and round-trips through `Registry.load`
- v1.15 `Model.price_expired(today) -> bool` is `True` exactly when `price_valid_until` is set and `today` is a later day; on the stated day itself the price is still valid. `today` is a `datetime.date`, and a `datetime.datetime` counts as its own date; any other type raises `TypeError`
- `Model.cost(input_tokens: int, output_tokens: int) -> float` returns `(input_tokens * price_in + output_tokens * price_out) / 1_000_000`
- `class Registry`: `Registry(models: Iterable[Model])`; `Registry.load(path) -> Registry` reads the models.json format (section 9); `.models -> tuple[Model, ...]` in file order; `.get(model_id) -> Model` raises `KeyError` for an unknown ID; duplicate IDs raise `ValueError` at construction
- v1.15 `Registry.load` reads the optional `price_valid_until` key of a row (absent or `null` means `None`; an invalid value raises `ValueError` naming the file, as any invalid row does), and `Registry.expired_prices(today) -> tuple[Model, ...]` returns the models whose `price_expired(today)` is true, in file order

### 4.2 Task (`tasks.py`)
- `@dataclass(frozen=True) class Task` fields and defaults:
  - `name: str`
  - `bar: float` (required, in [0, 1]; the minimum acceptable success rate against the task's acceptance check, for a judge its agreement with gold labels)
  - `min_samples: int = 30` (fewer measured trials than this can never clear the bar)
  - `confidence: float = 0.95`
  - `independent_of_generator: bool = True` (exclude the generator's model AND its family when the caller names a `generator_model`; no effect otherwise)
  - `exclude_families: tuple[str, ...] = ()`
  - `expected_input_tokens: int = 1000`, `expected_output_tokens: int = 200`
  - `on_no_model: str = "refuse"` (or `"best_available"`)
  - `max_fallbacks: int = 2`
  - `prior_category: str | None = None`
  - `timeout_s: float = 60.0`
- Invalid values raise `ValueError` at construction: bar outside [0, 1], `min_samples < 1`, confidence outside (0, 1), unknown `on_no_model`, negative token counts or `max_fallbacks`
- `load_tasks(path) -> dict[str, Task]` reads `{"tasks": [ {field: value, ...}, ... ]}`; JSON lists become tuples; duplicate names raise `ValueError`

### 4.3 Quality statistics (`stats.py`)
- `wilson_lower_bound(successes: int, trials: int, confidence: float = 0.95) -> float`
  - z = `NormalDist().inv_cdf(1 - (1 - confidence) / 2)` (two-sided interval, lower end); p = successes / trials
  - LB = `(p + z*z/(2n) - z*sqrt(p*(1-p)/n + z*z/(4n*n))) / (1 + z*z/n)`, clamped to `>= 0.0`
  - returns `0.0` when `trials == 0`; raises `ValueError` when `successes < 0`, `trials < 0` or `successes > trials`
  - reference values at confidence 0.95 (to 6 decimals): (27, 30) 0.743789; (45, 50) 0.786398; (90, 100) 0.825634; (170, 200) 0.793944; (10, 10) 0.722467; (0, 10) 0.0
- `class Stats`: in-memory map from `(task, model_id)` to `(successes, trials)`
  - `Stats()`; `.get(task, model_id) -> tuple[int, int]` returns `(0, 0)` when absent; `.add(task, model_id, successes, trials)` accumulates (adds to existing counts) and validates like `wilson_lower_bound`
  - `Stats.load(path)` and `.save(path)` use `{"stats": [{"task": ..., "model": ..., "successes": int, "trials": int}, ...]}`; save writes rows sorted by (task, model)
  - `.merge(other: Stats) -> Stats` returns a new Stats with summed counts
- `calibrate_from_results(rows: Iterable[dict]) -> Stats`: each row has `task`, `model`, and either `correct` (bool) or both `prediction` and `gold` (correct when equal with `==`); a row with neither raises `ValueError`. Each row is one trial
- v1.1 validation: `correct` must be a real boolean (`type(correct) is bool`); a string such as `"false"`, a number or null raises `ValueError`. A row that is not a dict raises `ValueError`. `Stats.load` requires `successes` and `trials` to be integers that are not booleans (`isinstance(v, int) and not isinstance(v, bool)`); floats such as `30.9`, strings and booleans raise `ValueError`, never truncation
- v1.33 measured token counts: `Stats` also holds, per `(task, model_id)`, optional token totals: `input_tokens` and `output_tokens`, the summed input and output tokens of `token_trials` of its trials, the calls whose token counts were recorded. A key with none has all three at 0. Token totals only come with trials, so `0 <= token_trials <= trials` always holds, and a model with token totals is measured (`trials > 0`, 5.3)
- v1.33 `.add(task, model_id, successes, trials, *, input_tokens=None, output_tokens=None, token_trials=None)`: `input_tokens` and `output_tokens` are given together or not at all. Given, each is an integer `>= 0` that is not a bool, and they are totals over `token_trials` of this call's `trials`; `token_trials` defaults to `trials` and must be an integer that is not a bool with `1 <= token_trials <= trials`, so tokens cannot come with zero trials. One total without the other, `token_trials` without the totals, or any invalid value raises `ValueError`, and nothing is added when `add` raises
- v1.33 `.tokens(task, model_id) -> tuple[int, int, int]` returns `(input_tokens, output_tokens, token_trials)`, `(0, 0, 0)` when none are recorded. `.mean_tokens(task, model_id) -> tuple[int, int] | None` returns the mean input and output tokens per recorded call, each rounded up to an integer in integer arithmetic (`-(-total // token_trials)`, never through a float), or `None` when `token_trials` is 0. Rounding up means a model is never priced below the mean list cost of its recorded calls (`Model.cost` is linear in the token counts), though one call may cost more than its mean; integers keep `Model.cost` on whole token counts, as everywhere else
- v1.33 `.merge` sums the token totals and `token_trials` as it sums the counts. `.get` and `.items()` are unchanged and carry no tokens
- v1.33 files: a `Stats.load` row may carry `input_tokens`, `output_tokens` and `token_trials`, all three or none. A partial set, a value that is a bool, null or anything but an integer, a negative total, or a `token_trials` outside `1..trials` raises `ValueError` naming the file. Rows for the same key accumulate as before. `.save` writes the three keys, after `trials` and in that order, only for a key with `token_trials > 0`, so a Stats with no token totals saves the bytes v1.32 saves and a v1.32 file loads unchanged
- v1.33 `calibrate_from_results`: a row may carry `input_tokens` and `output_tokens`, both or neither, each an integer `>= 0` that is not a bool (one without the other, null, a float or a string raises `ValueError`, and every row is still validated before the returned Stats exists). A row with them adds one token trial with those counts; a row without them adds a trial with none. The `calibrate` command (10) needs no change: its printed table is unchanged, and the file it writes carries the token keys of the rows that had them

### 4.4 Priors (`priors.py`)
- Leaderboard numbers are not agreement rates, so priors NEVER clear a bar. They only order candidates when nothing has been measured (cold start) and tell you which models to calibrate first
- `Priors.load(path)` reads `{"categories": {name: {"metric": str, "source": str, "as_of": str, "scores": {model_id: number}}}}`; `Priors(categories: dict)` takes the same inner dict
- `.score(category, model_id) -> float | None`; unknown category or model returns `None`
- `.ranked(category) -> list[str]` model IDs by descending score, ties by ascending ID

## 5. Routing (`router.py`)

### 5.1 Types
- Reason codes (module constants with these exact string values): `EXCLUDED_MODEL = "excluded_model"`, `EXCLUDED_FAMILY = "excluded_family"`, `GENERATOR = "generator"`, `GENERATOR_FAMILY = "generator_family"`, `CONTEXT_TOO_SMALL = "context_too_small"`, `INSUFFICIENT_SAMPLES = "insufficient_samples"`, `BELOW_BAR = "below_bar"`, `PASSES = "passes"`
- `@dataclass(frozen=True) class Candidate`: `model_id`, `family`, `successes`, `trials`, `quality_lb: float`, `routing_cost: float`, `list_cost: float`, `eligible: bool`, `passes: bool`, `reason: str`
- `@dataclass(frozen=True) class RouteDecision`: `task: str`, `flavor: str`, `primary: str`, `fallbacks: tuple[str, ...]`, `below_bar: bool`, `basis: str` (`"measured"` or `"prior"`), `candidates: tuple[Candidate, ...]` (one per registry model, registry order); `.to_dict()` returns plain JSON-able types (tuples become lists, candidates become dicts)
- `class NoModelClearsBar(Exception)` with attribute `.candidates` (the tuple above)
- Flavor names: `"cost_effective"`, `"cost_blind"`; anything else raises `ValueError`

### 5.2 `Router(registry, tasks: dict[str, Task], stats: Stats, priors: Priors | None = None)`
The constructor stores its arguments as attributes `.registry`, `.tasks`, `.stats`, `.priors`.
`.select(task_name, flavor="cost_effective", generator_model=None, exclude_models=()) -> RouteDecision`; unknown task raises `KeyError`. Steps, in order, per registry model (the first rule that applies sets `reason`):
1. ID in `exclude_models`: `excluded_model`
2. family in `task.exclude_families`: `excluded_family`
3. `independent_of_generator` and ID equals `generator_model`: `generator`
4. `independent_of_generator` and family equals the generator's family (generator looked up in the registry; an unknown generator ID raises `KeyError`): `generator_family`
5. `context_window < expected_input_tokens + expected_output_tokens`: `context_too_small`
6. measured `trials < task.min_samples`: `insufficient_samples` (still eligible for the cold-start path below)
7. `wilson_lower_bound(successes, trials, task.confidence) < task.bar`: `below_bar`
8. otherwise `passes`
- `eligible` is True for reasons 6 to 8; `passes` only for 8
- `list_cost = model.cost(expected_input_tokens, expected_output_tokens)` (from v1.33 at the model's sizes, below); `routing_cost = list_cost` for `cost_effective`, `0.0` for `cost_blind`
- `quality_lb = wilson_lower_bound(successes, trials, confidence)` for every candidate (0.0 when unmeasured)
- v1.33 sizes: a model's **sizes** for the task are `stats.mean_tokens(task, model_id)` when that is not `None`, else `(expected_input_tokens, expected_output_tokens)`, and `list_cost` is `model.cost` of its sizes. So a model measured with token counts is priced at what it read and wrote per call on this task, and any other model at the task's expected tokens. Rule 5 keeps the task's expected tokens for every model: a mean is not a bound on one call, so it cannot say whether a call fits (set the task's sizes to the longest calls you expect). Measured token counts therefore change a candidate's `list_cost` and `routing_cost` and the 5.3 orders that use them, never its `reason`, `eligible` or `passes`. `Candidate` gains no field. With no token totals in the stats, every candidate and decision is v1.32's, bit for bit

### 5.3 Choosing
- If any candidate passes: sort passing candidates by `(routing_cost, -quality_lb, model_id)`; `primary` is the first; `fallbacks` are the next `max_fallbacks`; `below_bar=False`; `basis="measured"`
- Else if `on_no_model == "refuse"`: raise `NoModelClearsBar`
- Else (`best_available`): among eligible candidates with `trials > 0`, sort by `(-quality_lb, routing_cost, model_id)`; if that list is non-empty use it (`basis="measured"`); otherwise, if the router has priors and the task has `prior_category`, use eligible candidates that have a prior score, sorted by `(-score, routing_cost, model_id)` (`basis="prior"`); `primary` is the first, `fallbacks` the next `max_fallbacks`, `below_bar=True`; if both lists are empty raise `NoModelClearsBar`
- Note: in `cost_blind` the passing sort reduces to `(-quality_lb, model_id)`, so the best measured model wins

## 6. Providers (`providers.py`)
- `@dataclass(frozen=True) class Completion`: `text: str`, `input_tokens: int`, `output_tokens: int`
- `class ProviderError(Exception)`: any failure a fallback should handle (timeout, rate limit, 5xx, bad response)
- `class Provider(Protocol)`: `complete(self, model_id: str, messages: list[dict], timeout_s: float) -> Completion`
- `FakeProvider(script: dict[str, Callable[[list[dict]], Completion]])`: calls `script[model_id](messages)`; an exception raised by the callable propagates unchanged; a model ID not in the script raises `ProviderError`. `.calls` is a list of `(model_id, messages)` in call order
- `OpenAICompatibleProvider(base_url: str, api_key_env: str = "OPENAI_API_KEY", model_map: dict[str, str] | None = None)`: POSTs `{"model": mapped_id, "messages": messages}` to the endpoint `base_url.rstrip("/") + "/chat/completions"`; v1.1: when `base_url` has a query string (for example `?api-version=...`), `/chat/completions` is appended to the path and the query is kept after it (`https://h/v1?q=1` posts to `https://h/v1/chat/completions?q=1`) with `Authorization: Bearer <key>` via `urllib.request`, reads `choices[0].message.content` and `usage.prompt_tokens` / `usage.completion_tokens`; any network, HTTP or parse failure raises `ProviderError`. v1.1 redaction: no `ProviderError` the adapter raises may contain the API key value in `str()`, `repr()` or its exception chain; the adapter replaces every occurrence of the key with `[redacted]` in the message and raises with `from None`; every URL anywhere in a message, including URLs inside text taken from the opener's exception, the HTTP reason and the HTTP body, is shown without userinfo, query string or fragment (`scheme://host[:port]/path`); in addition the password and every query parameter value of `base_url` that is at least 8 characters long, in both its raw form as written in `base_url` (percent escapes and `+` intact) and its decoded form, are replaced with `[redacted]` wherever they appear on their own (the password likewise in both forms) (shorter values such as `v=1` or `beta=true` cannot carry a credential and would only mangle the message; the API key is redacted whatever its length), so credentials embedded in `base_url` never reach a message or a log. If formatting the underlying exception or its HTTP reason itself raises, the adapter still raises `ProviderError` (naming only the exception class) and nothing from the failed formatting leaks. The constructor raises `ValueError` for a `base_url` that is not an `http` or `https` URL with a host, and that message never contains the URL (no `__cause__`, `__suppress_context__` True). For an `urllib.error.HTTPError` the message includes the status code and at most the first 200 characters of the response body, after redaction, and the error has attribute `.status` (int, else `None` on non-HTTP failures). `timeout_s` is passed to the opener and bounds each blocking socket operation (urllib semantics), not the total call. Works with any OpenAI-compatible endpoint (vendor APIs, gateways, local servers). Tests must not touch the network: it accepts an optional `opener` callable (default `urllib.request.urlopen`) for injection

## 7. Execution with fallback (`executor.py`)
- `@dataclass(frozen=True) class Attempt`: `model: str`, `outcome: str` (`"ok"`, `"error"` or `"invalid"`), `error: str | None` (exception class name and message for errors, `"validation failed"` for invalid), `latency_ms: float`, `input_tokens: int`, `output_tokens: int`, `cost_usd: float`
- `@dataclass(frozen=True) class CallResult`: `call_id: str`, `text: str`, `model: str`, `attempts: tuple[Attempt, ...]`, `decision: RouteDecision`
- `class AllModelsFailed(Exception)` with `.attempts` and `.decision`
- `Executor(router, provider, monitor=None, clock=time.monotonic, now=None, id_factory=None)`; `now` returns an ISO 8601 UTC string (default: current UTC time); `id_factory` returns a call ID (default: `uuid.uuid4().hex`)
- `.call(task_name, messages, flavor="cost_effective", generator_model=None, exclude_models=(), tags=None, validate=None) -> CallResult`
  1. `decision = router.select(...)` (its exceptions propagate)
  2. for each model in `(primary, *fallbacks)`: time `provider.complete(model, messages, task.timeout_s)` with `clock`
     - `ProviderError` raised: attempt outcome `error`, tokens 0, cost 0.0; continue. Any other exception propagates (it is a bug, not an outage)
     - `validate` given and `validate(text)` is falsy: outcome `invalid`, tokens and cost from the completion; continue
     - otherwise: outcome `ok`; stop
  3. every attempt is passed to `monitor.record(...)` (when a monitor is given) as it happens, using the record schema in 8.1
  4. no `ok` attempt: raise `AllModelsFailed`
- `cost_usd` of an attempt is the list-price cost of its actual tokens: `registry.get(model).cost(input_tokens, output_tokens)`
- Helper `json_validator(*required_keys) -> Callable[[str], bool]`: True when the text parses as a JSON object containing every key
- v1.11: `.call_delegated(decision, messages, tags=None, validate=None) -> CallResult` runs the hand-off of a `DelegationDecision` (13.6) whose `mode` is `"delegate"`. `messages` is the brief the parent wrote. Steps 2 to 4 of `.call` run over `(decision.route.primary, *decision.route.fallbacks)` with the `timeout_s` of the task named `decision.task` in this executor's router (an unknown task raises `KeyError`), and `CallResult.decision` and `AllModelsFailed.decision` are `decision.route`. The route is used as decided: `select` is not called again, so a stats change after the decision does not move the call
  - Every record's `flavor`, `below_bar` and `basis` come from `decision.route`, and its `tags` are the caller's tags plus `"delegated": "true"` and `"parent": decision.parent`, so `report --by tag:delegated` and `--by tag:parent` split the spend. The caller's dict is not modified
  - `ValueError`, raised before any provider call and any record: a decision whose `mode` is not `"delegate"` (inline work happens in the parent's own call, so there is nothing to run), a `delegate` decision whose `route` is `None` (one built by hand; `decide_delegation` never returns one), and a caller tag named `delegated` or `parent`
  - `.call` is unchanged: it still looks its task up under the caller's `task_name` and names that key in `AllModelsFailed`, after `select` and before `id_factory` and the first provider call
  - The records cover the delegate's calls only. The parent's share of `delegate_cost_usd` (writing the brief, re-reading it and the result, 13.2) is spent in the parent's own calls, which this executor does not see

## 8. Monitoring and cost attribution (`monitor.py`)

### 8.1 Record schema (one JSON object per attempt)
`ts` (str), `call_id` (str), `task` (str), `flavor` (str), `model` (str), `family` (str), `attempt` (int, 0-based index within the call), `final` (bool, True on the call's last attempt), `outcome` (str), `error` (str or null), `latency_ms` (float), `input_tokens` (int), `output_tokens` (int), `cost_usd` (float, list price, recorded in both flavors), `routing_cost_usd` (float: equals `cost_usd` in `cost_effective`, `0.0` in `cost_blind`), `below_bar` (bool), `basis` (str), `tags` (object of string to string; `{}` when none; v1.11: `call_delegated` adds `delegated` and `parent`, 7)

### 8.2 `Monitor(path=None)`
- `.record(rec: dict)` appends to `.records` (a list) and, when `path` is set, appends one JSON line to that file
- `load_records(path) -> list[dict]` reads a JSONL file, skipping blank lines. v1.1: a non-blank line that is not valid JSON, or is valid JSON but not an object, raises `ValueError` whose message contains the path and the 1-based line number (for example `calls.jsonl:3`)

### 8.3 `report(records, by="model") -> list[dict]`
- `by` is `"model"`, `"task"`, `"flavor"`, `"family"`, or `"tag:<key>"` (records without that tag group under `"(none)"`); anything else raises `ValueError`
- Attempt-level sums per group use each attempt's own value: `attempts`, `ok`, `errors`, `invalid`, `input_tokens`, `output_tokens`, `cost_usd`, `routing_cost_usd` (costs rounded to 6 decimals)
- Call-level metrics use the call's FINAL attempt to pick the group: `calls` (calls whose final attempt is in the group), `failed_calls` (final outcome not ok), `fallback_calls` (final attempt index > 0), `fallback_rate` (`fallback_calls / calls`, 0.0 when no calls)
- `p50_latency_ms`, `p95_latency_ms`: nearest-rank percentile over the group's `ok` attempts (sorted ascending, index `ceil(q * n) - 1`), `None` when there are none
- Each row is a dict with key `group` plus the keys above; rows sorted by descending `cost_usd`, then `group`

## 12. Offline evaluation (`evaluate.py`, v1.3)
Purpose: show from a public outcome matrix, with no API key, whether routing at a bar holds that bar on items it never saw, and what it costs next to simple baselines. The evaluator routes through `Router.select`, so the evidence exercises the shipped rules (min_samples, the Wilson admission rule, the 5.3 sort keys) and not a re-implementation of them.

### 12.1 Outcome matrix
- JSONL, one object per (task, item, model): `task` (str), `item` (str), `model` (str), `correct` (bool, strict as in 4.3), and the cost of that one call as either `cost_usd` (an int or float that is not a bool, finite and `>= 0`) or both `input_tokens` and `output_tokens` (integers `>= 0` that are not bools), priced with `registry.get(model).cost(input_tokens, output_tokens)`. When `cost_usd` is present it is used and token counts are ignored. Extra keys are ignored
- `@dataclass(frozen=True) class Outcome`: `task: str`, `item: str`, `model: str`, `correct: bool`, `cost_usd: float`
- `outcomes_from_rows(rows: Iterable[dict], registry: Registry | None = None) -> tuple[Outcome, ...]`, in input order. `ValueError` for: a row that is not a dict; `task`, `item` or `model` missing or not a non-empty string; `correct` missing or not a bool; neither `cost_usd` nor both token counts; an invalid cost or token value; a token-form row when `registry` is `None` or does not contain the model; a repeated (task, item, model)
- `load_outcomes(path, registry: Registry | None = None) -> tuple[Outcome, ...]` reads JSONL and skips blank lines; a non-blank line that is not valid JSON, or is not an object, raises `ValueError` whose message contains `<path>:<line>` (1-based) as in 8.2; rows are then validated as above

### 12.2 Split
- `split_items(items: Iterable[str], seed: int, calibration_fraction: float = 0.5) -> tuple[tuple[str, ...], tuple[str, ...]]` returns `(calibration, held_out)`, each sorted ascending with duplicates collapsed. An item is in calibration exactly when `int.from_bytes(hashlib.sha256(f"{seed}:{item}".encode("utf-8")).digest()[:8], "big") < calibration_fraction * 2**64`; otherwise it is held out. The split depends only on the seed and the item ID, so it is the same on every machine and for every row order
- `calibration_fraction` outside the open interval (0, 1) raises `ValueError`

### 12.3 `evaluate(outcomes, bars, seeds=range(10), flavors=("cost_effective", "cost_blind"), calibration_fraction=0.5, min_samples=30, confidence=0.95) -> dict`
- Checked before any work, each a `ValueError`: no outcomes; no bars, a bar that is a bool, not an int or float, not finite (so NaN is rejected) or outside [0, 1], or a repeated bar; no seeds, a seed that is a bool or not an int, or a repeated seed; no flavors, a name not in 5.1, or a repeated flavor; `min_samples < 1`; confidence outside (0, 1); `calibration_fraction` as in 12.2; an incomplete matrix (every model that appears anywhere must have a row for every (task, item) pair that appears anywhere; the message names one missing (task, item, model)); a (task, seed) whose calibration or held-out split is empty (the message names the task and the seed)
- The empty-split rule is deliberately strict: a task with very few items would otherwise be scored on a handful of items in some seeds and not at all in others. When it trips, drop or enlarge that task, use fewer seeds, or move `calibration_fraction` toward 0.5
- One **cell** per (bar, flavor, seed, task), nested in that order: bars, flavors and seeds in the order given, tasks ascending. In a cell, C and H are the task's calibration and held-out items from `split_items(task_items, seed, calibration_fraction)`
  - calibration counts per model: successes = correct rows in C, trials = |C|; mean calibration cost = total cost over C divided by |C|
  - `routed`: the primary of `Router.select(task, flavor)` for a task with this `bar`, `min_samples` and `confidence` and `on_no_model="best_available"`, over a registry in which each model's list cost per call equals its mean calibration cost (so `cost_effective` ranks by measured cost) and no model is excluded by rules 1 to 5 of 5.2. `cleared` is `not decision.below_bar`
  - `cheapest`: the model with the lowest mean calibration cost, ties by model ID
  - `best_on_calibration`: the model with the highest calibration success rate, ties by lower mean calibration cost, then model ID (no bar and no confidence bound)
  - `oracle`: on each held-out item it is correct when any model is correct, and its cost is the lowest cost among the correct models on that item, or the lowest cost among all models when none is correct
  - `model:<id>` for every model in the matrix: that model on every held-out item
  - for every strategy, `success` = correct held-out items / |H| and `cost_usd` = total cost over H
- Strategy order everywhere: `routed`, `oracle`, `best_on_calibration`, `cheapest`, then `model:<id>` by ascending ID
- Cell keys: `bar`, `flavor`, `seed`, `task`, `calibration_items` (int), `held_out_items` (int), `cleared` (bool), `models` (`{"routed": id, "best_on_calibration": id, "cheapest": id}`), and `success` and `cost_usd`, each a dict keyed by strategy name in strategy order
- Return value keys:
  - `config`: `bars`, `seeds` and `flavors` (lists, in the order given), `calibration_fraction`, `min_samples`, `confidence`
  - `tasks`: `{task: {"items": int, "models": [ids ascending]}}`
  - `cells`: the cells above, in cell order
  - `summary`: one row per (bar, flavor, strategy), in that order, with keys `bar`, `flavor`, `strategy`, `success` (mean over seeds of that seed's item-weighted held-out success across all tasks: total correct held-out items / total held-out items), `cost_usd` (mean over seeds of that seed's total held-out cost across all tasks), `below_bar_rate` (fraction of that strategy's (task, seed) cells whose held-out success is below the bar), `cleared_rate` (for `routed`, the fraction of cells with `cleared`) and `bar_violation_rate` (for `routed`, among cleared cells the fraction whose held-out success is below the bar, `None` when no cell cleared); the last two are `None` for every other strategy
  - `per_task`: one row per (bar, flavor, task, strategy), in that order, with the summary keys plus `task` and `routed_models`; `success` and `cost_usd` are means over seeds of that task's cell values, the three rates count that task's cells only, and `routed_models` is `{id: number of seeds routed to it}` for `routed` and `None` otherwise
- Arithmetic: every success rate and every rate is an integer count divided by an integer count (for the summary `success`, total correct held-out items over total held-out items, both integers). Every cost total, and the sum behind every mean, is computed with `math.fsum`, which is exactly rounded and so independent of summation order; a mean is that sum divided by its count
- Granularity: in `summary`, `success` and `cost_usd` weight every held-out item equally within a seed, while `below_bar_rate`, `cleared_rate` and `bar_violation_rate` count (task, seed) cells, so a small task weighs as much as a large one in the rates but not in `success`. `success` above the bar does not imply a zero `below_bar_rate`
- Deterministic: the same outcomes in any row order with the same arguments give an equal dict, and `json.dumps(result, sort_keys=True)` is byte-identical
- Reading the numbers: `wilson_lower_bound` is the lower end of a two-sided interval (4.3), so for one model judged once its nominal chance of admitting a true rate below the bar is about `(1 - confidence) / 2` (2.5% at 0.95), and that figure is approximate because Wilson coverage is not exact. Three things push the observed `bar_violation_rate` above it: the routed model is the cheapest (or best) of several passing models, and that selection favours models whose calibration rate came out high by chance; the held-out rate is itself a noisy estimate, so a model whose true rate sits just above the bar misses it on a small held-out set often; and the seeds are re-splits of one item pool, so cells are correlated rather than independent trials. Read the rate as a resampling estimate for this matrix, next to `(1 - confidence) / 2` and the held-out size, never as a guarantee and never against zero

### 12.4 CLI
- `model-routing evaluate --outcomes PATH [--bar B [B ...]] [--seeds K] [--calibration-fraction F] [--min-samples N] [--confidence C] [--registry PATH] [--json]`
  - `--bar` takes one or more values and may be repeated (default `0.8`); `--seeds K` means seeds `0` to `K - 1` (default 10, `K >= 1`); `--registry` defaults to the packaged models.json and is only used to price token-form rows; both flavors always run
  - prints one table per (bar, flavor) with a row per strategy and the columns success, cost_usd, below_bar_rate, cleared_rate and bar_violation_rate; `--json` prints the result without `cells` (keys `config`, `tasks`, `summary`, `per_task`) so a committed results file stays small
  - v1.5 text layout: for each (bar, flavor) in config order, a heading line `bar <bar>, <flavor>` (the bar as Python `str` prints it), then a table in the layout of the other commands (header, a dash row, one row per strategy in strategy order) with columns `strategy`, `success`, `cost_usd`, `below_bar_rate`, `cleared_rate`, `bar_violation_rate`, built from the `summary` rows; rates and success to 3 decimals, `cost_usd` to 4, `-` for `None`.   - exit codes: 0 success; 2 bad input (missing or unreadable file, bad JSON, invalid row, incomplete matrix, empty split, invalid option value), with a one-line `error: ...` message on stderr as for the other commands

A present file is verified and used, and one that fails `verify` is a `ValueError` naming it and is left in place (delete it to download again); a missing file is downloaded with `urllib.request.urlopen` from `https://huggingface.co/datasets/withmartian/routerbench/resolve/<revision>/routerbench_0shot.pkl` into a `.part` file next to it, verified, then renamed, and the `.part` file is removed when the check fails
- `verify(path, size=SIZE, sha256=SHA256)`: `ValueError` naming the expected and the actual value when the byte size or the sha256 differs. Nothing is unpickled before it passes
- `RestrictedUnpickler(pickle.Unpickler)`, `restricted_load(fileobj)` and `load_frame(path)`; `load_frame` opens the file, runs `restricted_load` and turns any other exception raised while unpickling (an empty or truncated file, an allowed callable given bad arguments) into a `ValueError` naming the file, so only `pickle.UnpicklingError` and `ValueError` leave it. In `restricted_load`, `find_class` resolves only the (module, name) pairs in `ALLOWED_GLOBALS`, exactly the 11 globals the pinned file references (found with a static `pickletools` opcode scan, which runs no code): `builtins.slice`, `numpy.dtype`, `numpy.ndarray`, `numpy.core.multiarray._reconstruct`, `numpy.core.numeric._frombuffer`, `pandas._libs.internals._unpickle_block`, `pandas.core.frame.DataFrame`, `pandas.core.indexes.base.Index`, `pandas.core.indexes.base._new_Index`, `pandas.core.indexes.range.RangeIndex`, `pandas.core.internals.managers.BlockManager`. Any other global raises `pickle.UnpicklingError` naming it, with no module-prefix wildcard; names are checked as written, with no Python 2 name mapping (`fix_imports=False`), and persistent IDs are refused. Because the file is hash-pinned, the list only has to cover that one file; a pickle written by another pandas or numpy version is refused, not trusted
- `model_id(column) -> str`: a column name of the form `vendor/model` (one `/`, both sides non-empty) is kept as is, and any other name containing `/` is a `ValueError`; a name starting `claude-` becomes `anthropic/<name>` and one starting `gpt-` becomes `openai/<name>`; anything else is a `ValueError` rather than a guess
- `frame_columns(frame) -> dict[str, list]`: `ValueError` naming the type when `frame` has no `columns` attribute (a pickle that loads to something other than a frame); otherwise plain Python lists, from `.tolist()`, for `sample_id`, `eval_name` and, for every model column `<m>`, both `<m>` (the score) and `<m>|total_cost`. A model column is any column without `|` other than `sample_id`, `prompt`, `eval_name` and `oracle_model_to_route_to`. Prompts and responses are never read. `ValueError` when `sample_id` or `eval_name` is missing, there is no model column, or a model has no `|total_cost` column
- `convert(columns, pass_score=None, min_items=100) -> tuple[list[dict], dict]`, where `columns` is what `frame_columns` returns (any `dict[str, list]` of that shape):
  - `ValueError`, checked before any output: columns of different lengths; a `sample_id` that is not a non-empty string or is repeated; an `eval_name` that is not a non-empty string; a score that is a bool, not an int or float, NaN or outside [0, 1]; a cost that is a bool, not an int or float, not finite or below 0 (score and cost messages name the `sample_id` and the column); `pass_score` that is not `None` and is a bool, not an int or float, or outside (0, 1] (so NaN is rejected); `min_items` that is a bool, not an int, or below 1; a model column that `model_id` rejects, or two columns mapping to one ID
  - each source row is one item: task = `eval_name`, item = `sample_id`, and one output row per model with model = `model_id(column)`, `cost_usd` = the recorded `total_cost` as a float, with a negative zero written as `0.0`
  - scores and costs must be Python `int` or `float` values (a `float` subclass such as numpy's float64 counts); other numeric types such as numpy's int64 or float32 are rejected, which `.tolist()` never produces but a hand-built `columns` dict could
  - graded tasks: a task is graded when any of its scores, for any model, is not exactly 0 or 1. With `pass_score=None` a graded task is dropped; otherwise it is kept. In a kept task `correct` is `score >= pass_score` when `pass_score` is set and `score == 1` when it is not, which agree on 0 or 1 scores for every allowed `pass_score`. The pinned file's graded tasks (`grade-school-math` with scores in {0, 0.25, 0.5, 0.75, 1}, `consensus_summary`, the `mtbench` tasks, `chinese_idioms`) do not document what a partial score means, so excluding them is the default and including them is the user's stated choice
  - small tasks: a task left with fewer than `min_items` items is dropped. The default 100 gives calibration and held-out halves of about 50 items, so in practice 12.3's empty-split rule does not trip and `min_samples = 30` can be met
  - output rows have the keys `task`, `item`, `model`, `correct`, `cost_usd` in that order, sorted by (task, item, model) as strings; they form the complete matrix 12.3 requires, and the result does not depend on the source row order
  - the report has keys `models` (IDs ascending), `kept`, `dropped_graded` and `dropped_small` (each `{task: number of items}` with tasks ascending) and `rows` (the number of output rows)
- `write_jsonl(rows, path)`: one `json.dumps(row)` per line, newline-terminated, in the given order
- CLI: `python evidence/routerbench/convert.py --out PATH [--cache DIR] [--pass-score T] [--min-items N]`, entry point `main(argv=None) -> int`. Options are checked first (no download for a bad one); then it fetches, verifies, loads with `load_frame`, converts and writes, and prints the report as `json.dumps(report, indent=2)`. It returns 0 on success and 2 with exactly one `error: ...` line on stderr and nothing on stdout for a missing or invalid option, a size or hash mismatch, a refused global, a file that does not unpickle to a frame, invalid data or an I/O error. The matrix is written to `<out>.part` and renamed onto `--out`; on any failure `--out` is not written and `<out>.part` is removed
- Reading it: the 11 models date from 2023 and the costs are the ones the dataset recorded at that time's prices; the evaluator routes per task (an `eval_name`), not per prompt

- `default_cache_dir()` is `~/.cache/ai-model-routing-evidence/autobench-2026/` (from `Path.home()`), never inside the repo. `fetch(cache_dir=None) -> Path` returns that folder after, for each file in `FILES` order: a present file is verified and kept, and one that fails `verify` is a `ValueError` naming it and is left in place; a missing one is downloaded with `urllib.request.urlopen` from `https://huggingface.co/datasets/AutoBench/router-benchmark-2026-10/resolve/<revision>/<name>` into `<name>.part`, verified, then renamed, and the `.part` file is removed when that fails. Last, `check_sums` runs on the text of `SHA256SUMS`
- `verify(path, size, sha256)`: `ValueError` naming the expected and the actual value when the byte size or the sha256 differs, as in 12.6
- `check_sums(text)`: reads lines of the form `<64 lowercase hex>  <name>` (two spaces, as `sha256sum` writes them); blank lines are skipped and any other line is a `ValueError`. `ValueError` when one of the four data files has no entry, or an entry that differs from `FILES` (the message names the file)
- `model_id(openrouter_id) -> str`: a string with exactly one `/` and both sides non-empty, else `ValueError`. Hyphens are removed from the vendor part with `re.sub("-", "", vendor)`, so `x-ai/grok-4.6` becomes `xai/grok-4.6` (models.json writes `xai/grok-4.7`) and `z-ai/glm-5.3` becomes `zai/glm-5.3`; the model part is kept as is. A rule, not a list, so a new hyphenated vendor needs no code change
- `pool_models(pool) -> dict[str, str]`: display ID to `model_id(openrouter_id)` for each entry of `pool["members"]`, in pool order. `ValueError` when `pool` is not a dict, `members` is missing or not a non-empty list, an entry is not a dict, a `display_id` or `openrouter_id` is not a non-empty string, a display ID repeats, or two entries map to one ID
- `pool_registry(pool) -> dict` (v1.21): a registry in the models.json format that `Registry.load` (4.1) reads, built from the pool's list prices: `{"source": {"dataset": "AutoBench/router-benchmark-2026-10", "revision": <the pinned revision>, "file": "pool.json"}, "models": [...]}`, one model per `members` entry, sorted by ID ascending so the pool order does not matter, each with the keys `id` (`model_id(openrouter_id)`), `family` (as written), `price_in` and `price_out` (`input_cost_per_mtok` and `output_cost_per_mtok` as floats, USD per 1M tokens, the unit of 4.1) and `context_window`, in that order. `ValueError` for an invalid pool as in `pool_models` (checked first, with its messages), and for a member whose `family` is not a non-empty string, whose `input_cost_per_mtok` or `output_cost_per_mtok` is not a finite number `>= 0` (a bool is not a number), or whose `context_window` is not an int `>= 1` (a bool is not an int); these messages name the display ID and the key. The prices are the pool's recorded list prices, frozen with it, so a cost from this registry is a list-price estimate (13.9), never the billed `cost`
- `delta_hit(score, pool_scores, width, top_k) -> bool`: the reference is the `math.fsum` of the `top_k` highest values of `pool_scores` divided by `top_k`, and the result is `score >= reference - width`. This is the dataset's Delta-Hit: with `width = delta_signal` and `top_k` from `frozen_params.json`, it gives the `delta_hit_signal` value of the dataset's `decisions.csv` on all 6,291 router decisions that carry one (checked when this section was written, against every scored pool cell of the question; `>` instead of `>=` also gives 6,291, so the boundary is not tested by the data)
- `convert(matrix, questions, pool, width, top_k=3, task_by="domain", tokens=False) -> tuple[list[dict], dict]`; `matrix` and `questions` are lists of dicts as `csv.DictReader` yields them (every value a string), `pool` is the parsed `pool.json`:
  - `ValueError`, checked before any output and the pool first, because `top_k` is bounded by its size: an invalid pool as in `pool_models`; a `width` that is a bool, not an int or float, not finite or `<= 0`; a `top_k` that is a bool, not an int, below 1 or above the number of pool models; a `task_by` other than `domain` and `all`; a `tokens` that is not a bool; a question whose `prompt_id` is not a non-empty string or repeats, or whose `ddc_domain` is not a non-empty string when `task_by` is `domain`; a matrix row whose `prompt_id` or `model` is not a non-empty string, whose `prompt_id` is not a question, or whose (`prompt_id`, `model`) pair repeats; for a pool model's row, a non-empty `score` that does not parse as a finite float, or a scored row whose `cost` does not parse as a finite float `>= 0` or, only when `tokens` is True, whose `input_tokens` or `output_tokens` is missing or does not parse as a finite float that is a whole number `>= 0` (these messages name the `prompt_id`, the model and, for a token count, the column)
  - repeated pairs: a (`prompt_id`, `model`) pair in two rows, for example once with `source` `original` and once with `fill_7_4`, is refused, never resolved by picking one. The pinned file has none: its 388 `fill_7_4` rows are all for 13 models outside the 20-model pool
  - out of pool: rows for a model that is not a pool display ID are dropped and counted (in the pinned file, exactly those 388 `fill_7_4` rows, which the dataset uses to grade router picks outside the pool)
  - unscored: an empty `score` is an unscored cell, and a pool model with no row for a question counts as one too. A question is kept only when every pool model has a score on it, so the output is the complete matrix 12.3 requires; a question with an unscored pool cell is dropped and counted, never scored as a miss
  - each kept question is one item: item = `prompt_id`; task = its `ddc_domain` as written (for example `9 History`), or `all` for every item when `task_by` is `all`; one row per pool model with model = its mapped ID, `correct` = `delta_hit(score, the scores of all pool models on that question, width, top_k)` and `cost_usd` = the billed `cost` as a float, with a negative zero written as `0.0`
  - output rows have the keys `task`, `item`, `model`, `correct`, `cost_usd` in that order, sorted by (task, item, model) as strings; the result does not depend on the row order of either file
  - tokens (v1.21): with `tokens` True each row also has `input_tokens` and `output_tokens`, in that order after `cost_usd`: that cell's `matrix.csv` columns written as ints (the pinned file writes them as, for example, `303.0`). `output_tokens` already counts the reasoning tokens (13.9), so `reasoning_tokens` is never read. With `tokens` False, the default, no token column is read, so the rows, the report and every error are those of v1.14. The report is the same in both
  - the report has keys `models` (IDs ascending), `width`, `top_k`, `task_by`, `kept` and `dropped_unscored` (each `{task: number of questions}` with tasks ascending), `unscored_cells` (pool cells with no score, missing rows included), `dropped_out_of_pool` (`{model as written: rows}`, ascending) and `rows` (the number of output rows)
- `read_csv(path) -> list[dict]` reads UTF-8 with `csv.DictReader`; `write_jsonl(rows, path)` as in 12.6
- CLI: `python evidence/autobench-2026/convert.py --out PATH [--cache DIR] [--width W] [--task-by {domain,all}] [--tokens] [--registry PATH]`, entry point `main(argv=None) -> int`. Options are checked first (no download for a bad one); then it fetches and checks the files, takes `top_k`, and `delta_signal` as the width unless `--width` is given, from `frozen_params.json`, converts, writes `<out>.part` and renames it onto `--out`, and prints the report as `json.dumps(report, indent=2)`. `--width 0.3011090610836323` is the dataset's official width (`delta_official`). `--tokens` (v1.21) passes `tokens=True`. `--registry PATH` (v1.21) also writes `json.dumps(pool_registry(pool), indent=2)` plus a newline to PATH; a `--registry` for which `--out`, `--registry` and their two `.part` paths do not resolve to four different files (for example `--registry` equal to `--out`, or `--out x.part --registry x`) is a usage error whose message says they name the same file, and an invalid pool for the registry fails before any file is written. Both files are written in full to their `.part` paths before either is renamed, `--out` first. A `--width` that is not a finite number `> 0` is a usage error whose message names the value; a `frozen_params.json` that is not an object, has no `top_k`, or has no `delta_signal` when `--width` is not given is invalid data whose message names the file and the key. It returns 0 on success and 2 with exactly one `error: ...` line on stderr and nothing on stdout for a bad option, a size, hash or `SHA256SUMS` mismatch, invalid data or an I/O error; on any failure before the renames neither `--out` nor `--registry` is written, and each `.part` file is removed
- Default options on the pinned files (checked when this section was written): 20 models; 203 of 252 questions kept, 49 dropped for 107 unscored pool cells; 4,060 rows; 10 domain tasks of 12 to 33 questions. Mean hit rate over all cells 0.667 at the default width and 0.762 at the official width. With `--tokens` (v1.21) the rows are the same with the two counts added: `input_tokens` 66 to 2,341 and `output_tokens` 3 to 42,188; 2 rows are billed 0, and on the other 4,058 the `--registry` list prices times those counts give a median ratio of 1.000 to the billed `cost`
- Reading it: a Delta-Hit is relative, not an absolute acceptance check. It means "rated about as well as the best three answers in this pool on this question" by a committee of up to 10 judge models taken from the same pool, so a hit depends on which other models were asked, and the ratings are model judgments, not gold labels. The costs are the billed USD per call in the matrix frozen on 2026-08-29 (the card dates the `fill_7_4` rows 2026-09-05, and every one of them is dropped). A domain has 12 to 33 kept questions, so its calibration half holds fewer than 30 items and the default `min_samples = 30` (5.3) cannot be met per domain; `--task-by all` pools them into one task of 203 items, which is the matrix the results slice commits (the per-domain matrix only as a stated sensitivity at a lower `--min-samples`)

### 12.11 Judge evidence: the AutoBench committee converter (`evidence/autobench-2026/judges.py`, v1.24; visible answer v1.26)
Purpose: public evidence for the first-class case, choosing a judge model, on 2026 models. AutoBench graded every answer with a committee of judge models and publishes each judge's grade, so a judge outcome matrix in the 12.1 format can be built from it with no API key. Standard library only (argparse, csv, importlib, itertools, json, math, sys, pathlib); the package never imports it
- Reuse: the script loads `convert.py` from its own folder by path with `importlib` and exposes that module as its attribute `convert`. The pinned revision, `FILES`, `fetch`, `verify`, `check_sums`, `pool_models`, `pool_registry`, `TASK_BY`, `read_csv`, `write_jsonl` and its whole-number token check `_count` (v1.25) are that module's (12.9), never copies, so the script holds no sha256 literal and no download code
- Data facts, checked on the pinned files when this section was written: `judges_json` is a JSON object {judge display ID: grade}, with exactly 10 judges on each of the 4,933 scored pool cells and `{}` on the 107 unscored ones; a grade is an int from 1 to 5, a float from 1.1 to 5.0, or `null` (738 nulls); the 14 judges are the pool's `judge_models`, all of them pool members, and `Kimi-k2.6` is listed on only 274 cells and grades 269 of them (5 `null`); the 4,933 cells carry 508 different judge sets, so no judge grades every cell; the dataset's `score` differs by more than 1e-6 from the plain mean of the non-null grades on 4,695 of the 4,933, so `score` only tells scored from unscored cells and the grades are read directly
- Terms: an **answer** is a scored pool cell (one `prompt_id` and the pool model that answered it); a **candidate** is a judge the router chooses among, a model of the output matrix; an answer's **graders** are its judges whose grade is not `null`; for a candidate c on an answer by model a, the **committee** is every grader other than c and a, so an answer model's grade of its own answer never enters a committee
- `judge_matrix(matrix, pool, tolerance=0.5, candidates=None, size=5, min_committee=3, rubric_tokens=400, grade_tokens=200, task_by="all", questions=None, answer_tokens="visible") -> tuple[list[dict], dict]` (`answer_tokens` v1.26, last so that positional calls keep their meaning); `matrix` and `questions` are lists of dicts as `csv.DictReader` yields them, `pool` is the parsed `pool.json`:
  - `ValueError`, before any output, in this order: an invalid pool as in `pool_models`; a `tolerance` that is a bool, not an int or float, not finite or `< 0`; `candidates` that is not `None` and not a non-empty list or tuple, holds an entry that is not a pool display ID, or repeats one; a `size` or `min_committee` (each `>= 1`), or a `rubric_tokens` or `grade_tokens` (each `>= 0`), that is a bool, not an int, or below its bound (`size` is checked even when candidates are given, which then ignore it); an `answer_tokens` that is not one of the strings `visible` and `output` (v1.26); a `task_by` not in `TASK_BY`; with `task_by` `domain`, `questions` that is not a list, or a question with no or a repeated `prompt_id` or no `ddc_domain` as in 12.9 (with `all`, `questions` is never read). Then per matrix row: not a dict, or a `prompt_id` or `model` that is not a non-empty string; with `domain`, a `prompt_id` that names no question; a repeated (`prompt_id`, `model`)
  - a row whose model is not a pool display ID is dropped and counted per name, and a pool row with an empty `score` is counted as unscored, before anything else in it is read. On every other row `judges_json` must be a JSON object with non-empty keys whose values are ints or floats (not bools, finite) or `null`, and `input_tokens` and `output_tokens`, and with `answer_tokens` `visible` also `reasoning_tokens` (v1.26), must be whole numbers `>= 0` as in 12.9 (the `_count` check, so an empty value is an error), checked in that order, so a row with several bad counts names the first; otherwise a `ValueError` naming the cell. With `output`, `reasoning_tokens` is never read, so the rows and the errors are those of v1.25. On the pinned files every scored pool cell has a whole `reasoning_tokens` (0 on 471 of them); the 118 empty values are on 94 of the 107 unscored pool rows and on 24 rows outside the pool, which are never read
  - candidates: the given ones, or by default the `size` judges, among the pool display IDs that grade at least one answer, whose set keeps the most answers under the rules below; ties go to the set whose ascending display IDs come first, which is the first such set in `itertools.combinations` order over the sorted IDs. Judges outside the pool may sit on committees but are never candidates, since they have no price. `ValueError` when `size` is more than those judges
  - each answer meets the first of these that applies and is counted under it: its answer model is a candidate (`dropped_self_graded`: generator isolation, 4.2, would never let a model grade its own answer, and dropping the whole answer keeps every candidate on every item); some candidate is not among its graders (`dropped_missing_candidate`, so the matrix is complete as 12.3 requires); it has fewer than `min_committee + 1` graders other than its answer model, so some committee would be smaller than `min_committee` (`dropped_small_committee`); otherwise it is kept. An answer with no graders at all is a missing-candidate drop, and a given candidate that grades no answer is accepted and keeps none, so no committee is ever empty
  - each kept answer is one item: item = `<prompt_id>|<the answer model's mapped ID>`; task = `all`, or the question's `ddc_domain` as written with `task_by` `domain`; one row per candidate with model = its mapped ID, `correct` = `abs(grade - mean) <= tolerance` in floating point as written, with no epsilon, where mean = `math.fsum` of the committee's grades divided by the committee size; `input_tokens` = the cell's `input_tokens` + the answer + `rubric_tokens` (the question, the answer and an assumed rubric), where the answer (v1.26) is `max(output_tokens - reasoning_tokens, 0)` with `answer_tokens` `visible`, the default, and the cell's `output_tokens` with `output`; and `output_tokens` = `grade_tokens` (an assumed grade length). Rows carry no `cost_usd`: they are token-form rows (12.1) that `model-routing evaluate --registry` prices with the registry `pool_registry` builds, at the pool's list prices, so every judge cost is an ESTIMATE, never a billed cost
  - row keys `task`, `item`, `model`, `correct`, `input_tokens`, `output_tokens` in that order, rows sorted by (task, item, model); the result does not depend on the order of the rows of either input
  - report keys, in order: `candidates` (mapped IDs ascending), `candidates_by` (`given` or `most_cells`), `tolerance`, `min_committee`, `rubric_tokens`, `grade_tokens`, `answer_tokens` (v1.26), `task_by`, `scored_cells` (the answers read), `kept` ({task: answers}, tasks ascending), `dropped_self_graded`, `dropped_missing_candidate`, `dropped_small_committee`, `self_graded_cells` (answers whose answer model is among their graders, kept or not: the cells a self-grading check would measure), `unscored_cells`, `dropped_out_of_pool` ({name: rows}, names ascending), `rows`. `scored_cells` equals the kept answers plus the three dropped counts
- The answer a judge reads (v1.26): a judge is shown the answer, never the answer model's reasoning, and a cell's `output_tokens` is the billed output count with the reasoning in it. On the 4,058 billed rows of 12.9, the `--registry` list prices times `input_tokens` and `output_tokens` give a median ratio of 1.000 to the billed `cost`, and 1.710 when `reasoning_tokens` is added on top (checked when this was written; 13.9 finds 1.001 and 1.718 on the 4,931 billed scored cells). So `visible`, the output less the reasoning, is the default estimate of the answer's length. The two counts are not exact: on 104 of the 4,933 scored cells `reasoning_tokens` is above `output_tokens`, by at most 21%, and there the floor counts the answer as 0 tokens, an underestimate, since its true length is unknown. `output` keeps the v1.25 estimate, an upper bound that counts the reasoning as read. The option changes only `input_tokens`: the candidates, the drops, the items and every `correct` are the same under both
- What the label is: a leave-one-out committee label, agreement with the other judges, and not a human gold label. A judge that always grades as the committee does scores 1.0 whether or not the committee is right, and a judge that is right where the committee is wrong scores lower. Answers to the same question are separate items, so the 12.2 split can put answers to one question in both halves
- CLI: `python evidence/autobench-2026/judges.py --out PATH [--cache DIR] [--registry PATH] [--tolerance T] [--candidates A,B,...] [--size K] [--min-committee N] [--rubric-tokens N] [--grade-tokens N] [--task-by {domain,all}] [--answer-tokens {visible,output}]`, each option defaulting to the function's (`--task-by` to `all`, `--answer-tokens`, v1.26, to `visible`; any other value is a usage error). It calls `convert.fetch(--cache)`, runs `judge_matrix` on the cached `matrix.csv` and `pool.json` (and `questions.csv` with `domain`) with `--candidates` split on commas, writes the rows as JSONL and, with `--registry`, `json.dumps(pool_registry(pool), indent=2)` and a newline (byte-identical to `convert.py --registry`), each through `<path>.part`, both written before either is renamed, with the `.part` files removed on failure; `--out`, `--registry` and their two `.part` paths must be four different files, as in 12.9. It prints `json.dumps(report, indent=2)` and exits 0, or exits 2 with one `error: ...` line on stderr (line breaks escaped) for a usage error (including an empty name in `--candidates`) or any `ValueError`, `OSError` or `csv.Error`. A failure before the renames writes no output file and leaves an existing one as it was; the two renames are not atomic together, so a failure in the second leaves `--out` renamed and `--registry` not, as in 12.9
- On the pinned files (a private prototype of this contract, run when this section was written, and the script since v1.25; the cached-file tests pin these): the default candidates are `deepseek/deepseek-v4-flash-0731`, `google/gemma-4-31b-it`, `meta/muse-glimmer-30b`, `openai/gpt-5.6-luna` and `tencent/hy3`; 756 of the 4,933 answers are kept (1,252 self-graded, 2,925 missing a candidate, 0 with a small committee), 3,780 rows; 2,478 answers are self-graded in all (2,514 list their answer model among their judges when `null` grades count); 107 unscored cells and 388 out-of-pool rows over 13 names. `size` 5 is the default as a trade between candidates and items: each candidate more cuts the kept answers by about a third (1,191 at 4, 756 at 5, 460 at 6), and at 5 the router still has 756 answer items, against the 203 question items of the 12.9 answer matrix. On the 756 kept answers, 707 report reasoning tokens, their `reasoning_tokens` summing to 0.738 of their `output_tokens`, and on 14 `reasoning_tokens` is above `output_tokens`, by at most 10% (counts of v1.25). v1.26: the floor applies to those 14, and with the default `visible` the judge input is 1,218,584 tokens per candidate over the 756 kept answers, 0.406 of the 3,001,074 that `output` counts (v1.26)
- Test status: `tests/test_evidence_autobench_judges.py` was committed before the script, under a module-level `pytest.mark.xfail(strict=True, raises=ModuleNotFoundError)`, which the implementing commit removed (v1.25). All but five tests use tiny in-memory tables. ## 13. Delegation: inline or sub-agent (`delegation.py`, v1.4; cost accounting v1.8)
Purpose: an agent (the **parent**: a model already running with its own context) reaches a piece of work that is one call of a task, or from v1.38 K successive calls of it (13.1). It can do the work itself (**inline**) or hand it to a fresh sub-agent running the model the router picks (**delegate**). The decision weighs what routing weighs, the measured success rate against the task's bar and list-price cost, plus what each path does to the parent's context. The delegate is chosen by `Router.select`, so the 5.2 rules, the Wilson admission rule and both flavors apply unchanged.

### 13.1 Inputs
`Router.decide_delegation(task_name, parent_model, flavor="cost_effective", *, context_tokens, brief_tokens, result_tokens, carry_turns=0, work_calls=1, inline_separate_call=True, cached_read_ratio=1.0, generator_model=None, exclude_models=()) -> DelegationDecision`
- `parent_model`: the parent's model ID. An unknown task, parent or `generator_model` raises `KeyError`; an unknown flavor raises `ValueError` (5.1)
- `context_tokens` (C): tokens already in the parent's context
- The work is one call of the task unless `work_calls` says more (v1.38): each call reads S_in = `task.expected_input_tokens` and writes S_out = `task.expected_output_tokens`; from v1.33 the cost of each path uses the 5.2 sizes of the model doing the work (13.2)
- `work_calls` (K, v1.38, default 1): the work is K successive calls of the task on one path. Each call takes S_in of new input and writes S_out, and call j (j = 1 to K) reads its path's base context (C inline, B delegated) plus the j inputs and the j - 1 outputs so far, so the path's context grows by S_in + S_out per call. K must be an integer `>= 1` that is not a bool, else `ValueError` naming `work_calls`, checked after `carry_turns`
- The bar and the bounds stay per call whatever K: K changes the cost of each path (13.2), the 13.4 context check and the delegate's `select` (13.3), never a success count, a bound or a bar check, so the 13.5 rows read the same bounds. `DelegationDecision` (13.6) has no field for K
- `brief_tokens` (B): what the parent writes to hand the work off. `result_tokens` (R): what the parent reads back
- `carry_turns` (T): parent calls after the parent's next call (13.2) that still re-read what this work leaves in its context. The next call itself is always charged, so T = 0 means the parent makes one more call after the work and stops. When the work is one of several sibling subtasks that the parent would otherwise do one after another, each later sibling done inline re-reads this one, so those calls count in T
- `inline_separate_call`: True (the default) when inline work takes a parent call of its own, False when the parent folds the work into its next call (13.2). It must be a bool, else `ValueError`
- `cached_read_ratio` (rho, v1.41, default 1.0): the price of the parent's cached re-reads of its existing context C, as a fraction of the parent's list input price, for a parent whose provider caches the prompt prefix it has already read; 13.2 says which reads it prices. It must be an `int` or a `float` that is not a bool, with 0 <= rho <= 1 (so NaN and the infinities fail), else `ValueError` naming `cached_read_ratio`, checked after `inline_separate_call`. It moves `inline_cost_usd` only: never `delegate_cost_usd`, the delegate's `select` (13.3), the 13.4 checks, a bound or a bar check. `DelegationDecision` (13.6) has no field for it
- `generator_model` and `exclude_models` mean what they mean in 5.2 and are passed to the delegate's `select`. `exclude_models` limits the delegate only; it never stops the parent working inline
- `context_tokens`, `brief_tokens`, `result_tokens` and `carry_turns` must be integers `>= 0` that are not bools, else `ValueError`
- The router is not modified: `router.tasks` is the same after the call

### 13.2 Cost of each path (list price, reported in both flavors)
The accounting follows the parent's calls, each of which re-reads the parent's whole context. Both paths are charged for the same calls, and each only for what that path adds to them:
- The **decision turn**, the parent call that makes this decision, happens on both paths. On the delegate path it also writes the brief, so B is charged once as parent output; on the inline path it writes nothing extra. Fetching the work's input is free on both paths; reading it is charged on both
- The parent's **next call** after the work is done (on the delegate path, the call that reads the result) and the T calls after it happen on both paths and re-read C on both, so C is not charged in them. Each of these 1 + T calls is charged for the tokens that the path left in the parent's context. What a call writes besides the work, the parent's own next step, is the same on both paths and is not charged
- The work itself: the delegate reads the brief and the work's input in a fresh context and writes the output. Inline, the parent does it either in a call of its own over its whole context (`inline_separate_call=True`) or inside its next call (`inline_separate_call=False`), which then also reads S_in and writes S_out. A separate call fits work that is a step of its own, for example output that goes into a tool call or a file before the parent goes on; folding fits work the parent would do as part of its very next reply anyway. The default, a separate call, gives the higher inline cost

With P the parent's model and D the delegate, for work of one call (K = 1; the v1.38 bullet below gives K calls):
- `delegate_cost_usd = P.cost(0, B) + D.cost(B + S_in, S_out) + (1 + T) * P.cost(B + R, 0)`: the brief written, the delegate's call, then the brief and the result re-read by the next call and the T after it
- `inline_cost_usd = P.cost(C + S_in, S_out) + (1 + T) * P.cost(S_in + S_out, 0)` when `inline_separate_call` is True: the parent's own call for the work, then its input and output re-read by the next call and the T after it
- `inline_cost_usd = P.cost(S_in, S_out) + T * P.cost(S_in + S_out, 0)` when `inline_separate_call` is False: the next call also reads S_in and writes S_out, and both are re-read by the T calls after it
- With K = 1, C appears only in the separate inline call. With a separate call, inline minus delegating to the parent's own model (D = P) is, in exact arithmetic, `P.cost(C, 0) - P.cost(B, B) + (1 + T) * (P.cost(S_in + S_out, 0) - P.cost(B + R, 0))`, so delegating even to its own model can save in two ways: the separate call's re-read of a large context C (the context-isolation case), and later calls that re-read a short brief and result instead of the work's input and output. When the work folds into the next call, C cancels, and delegating to the parent's own model is cheaper only when `T * P.cost(S_in + S_out, 0)` exceeds `P.cost(B, B) + (1 + T) * P.cost(B + R, 0)`, so never with T = 0
- Each expression is evaluated left to right as written, in floating point, from `Model.cost` (4.1); `1 + T` is an integer. `delegate_cost_usd` is `None` when there is no delegate
- v1.33: S_in and S_out in these expressions are the 5.2 sizes of the model doing the work on that path. In `inline_cost_usd` they are the parent's, S_in(P) and S_out(P), in its call for the work and in the later re-reads of that input and output; in `delegate_cost_usd` they are the delegate's, in `D.cost(B + S_in(D), S_out(D))`. For a model without measured token counts they are the task's expected tokens, so with no token totals each expression is the v1.32 one. With D = P both paths use the same sizes, so the D = P difference above holds with S_in(P) and S_out(P). The 12.3 evaluator builds its stats from counts alone, so its results do not move; from v1.35 the 13.9 harness adds each model's calibration-half token totals to its stats, so its decisions price each path at these per-model sizes (13.9)
- v1.38, K work calls (13.1). Write w_in = K(K + 1) / 2 and w_out = K(K - 1) / 2, both integers. The K calls of a path with base context X read `K * X + w_in * S_in + w_out * S_out` tokens in all and write `K * S_out`, and each path prices its K calls as one `Model.cost` of those integer totals, which is the sum of the K calls' costs in exact arithmetic since `Model.cost` is linear (4.1). S_in and S_out are the sizes of the model doing the work, as in v1.33. With P the parent and D the delegate:
  - `delegate_cost_usd = P.cost(0, B) + D.cost(K * B + w_in * S_in + w_out * S_out, K * S_out) + (1 + T) * P.cost(B + R, 0)`: the brief written once, the delegate's K calls, then the brief and the result re-read by the next call and the T after it
  - `inline_cost_usd = P.cost(K * C + w_in * S_in + w_out * S_out, K * S_out) + (1 + T) * P.cost(K * (S_in + S_out), 0)` when `inline_separate_call` is True: K parent calls of the work's own, each over the whole context, then the K inputs and outputs re-read by the next call and the T after it
  - `inline_cost_usd = P.cost((K - 1) * C + w_in * S_in + w_out * S_out, K * S_out) + T * P.cost(K * (S_in + S_out), 0)` when `inline_separate_call` is False: the last of the K calls is the parent's next call, which re-reads C on both paths, so C is charged only in the K - 1 calls before it. Folding takes the last work call into the next call, never all K
  - With K = 1, w_in = 1 and w_out = 0, so the token totals are the integers of the three expressions above and every cost, reason and check is the v1.37 one bit for bit
  - With a separate call, inline minus delegating to the parent's own model is, in exact arithmetic, `P.cost(K * C, 0) - P.cost(K * B, B) + (1 + T) * (P.cost(K * (S_in + S_out), 0) - P.cost(B + R, 0))`: each inline call re-reads C where each delegated one re-reads B, which is where context isolation pays most. Folded it is `P.cost((K - 1) * C, 0) - P.cost(K * B, B) + T * P.cost(K * (S_in + S_out), 0) - (1 + T) * P.cost(B + R, 0)`, so from K = 2 a large C can make delegating to its own model cheaper even with T = 0
- v1.41, cached context reads (13.1). The reads rho prices are the parent's reads of C in the inline work calls: the K calls of its own when `inline_separate_call` is True, the K - 1 calls before its next call when it is False. They are the only reads of C that 13.2 charges (the decision turn, the next call and the T calls after it read C on both paths and are not charged), and each of them finds C as the prefix of its prompt, just read by the decision turn. Those K * C or (K - 1) * C tokens are priced at rho times the parent's list input price; everything else stays at list price on both paths: the work's input and output, their re-reads by later work calls and by the 1 + T later parent calls, the brief, the result, every read of the delegate, and all output. With P the parent:
  - `inline_cost_usd = P.cost(K * C * rho + w_in * S_in + w_out * S_out, K * S_out) + (1 + T) * P.cost(K * (S_in + S_out), 0)` when `inline_separate_call` is True
  - `inline_cost_usd = P.cost((K - 1) * C * rho + w_in * S_in + w_out * S_out, K * S_out) + T * P.cost(K * (S_in + S_out), 0)` when `inline_separate_call` is False
  - `delegate_cost_usd` is the v1.38 expression whatever rho, and so is the delegate
  - The first argument of `P.cost` is evaluated left to right: the integer `K * C` or `(K - 1) * C`, times rho, then the integer terms added, so with a float rho it is a float. With rho = 1.0 its value is the v1.38 integer total, and `Model.cost` converts an int to that same float before it multiplies by a float price, so every cost, reason and check is the v1.40 one bit for bit (while the token totals and their products with the prices stay below 2^53, about 9e15); with the int rho = 1 the argument is the v1.38 integer itself. Folded work of one call has no C term, so its cost is the same for every rho
  - In exact arithmetic rho scales the C term of each inline minus delegating difference in the v1.38 bullet. With a separate call it is `P.cost(K * C * rho, 0) - P.cost(K * B, B) + (1 + T) * (P.cost(K * (S_in + S_out), 0) - P.cost(B + R, 0))`, so at rho = 0 the parent's context no longer favours delegating to its own model, and only later calls that re-read a short brief and result instead of the work can; folded, the C term is `P.cost((K - 1) * C * rho, 0)`
  - Not modelled: a surcharge for writing the cache, a cache that expires between calls, a discount on any other re-read on either path, and a cached price for the delegate. rho is one number the caller states for the parent; the AutoBench pool (13.9) has no cached prices, so evidence with rho < 1 states it as an assumption
- This is still an approximation. It assumes that each of the K work calls reads its path's base context and every earlier work call in full, with nothing summarised between calls (13.8), no prompt caching beyond the v1.41 ratio on the parent's reads of C, the same parent output after the work on both paths (checking a delegate's result may take more), and that the parent's later calls fit its context on both paths: C + K * (S_in + S_out) is checked for inline (13.4) but C + B + R is not checked for delegate

### 13.3 The delegate
- The delegate is the primary of `Router.select(task_name, flavor, generator_model, exclude_models)` run with the same registry, stats and priors on a copy of the task whose `expected_input_tokens` is `S_in + B`, so the context rule (5.2 rule 5) and the `cost_effective` ranking see the brief the delegate actually reads. It may be the parent's own model
- `route` is that `RouteDecision`, or `None` when that `select` raises `NoModelClearsBar`. `delegate_quality_lb` is the `quality_lb` of the route's primary candidate. The delegate clears the bar when `route.below_bar` is False
- The parent's share of `delegate_cost_usd` is the same for every delegate, so the `cost_effective` primary of this `select` is also the passing delegate with the lowest `delegate_cost_usd`
- v1.33: in that `select` every model's input size is its 5.2 input size plus B, so a model with measured token counts is priced at `model.cost(mean input + B, mean output)` and any other at `model.cost(S_in + B, S_out)`, which keeps the bullet above true; rule 5 still checks the copy's expected tokens, S_in + B + S_out. One way is a private copy of the stats with B times `token_trials` added to each input total, since rounding up `(I + B * n) / n` gives the rounded-up `I / n` plus B exactly. `router.stats` and `router.tasks` are the same after the call
- v1.38, K work calls: in that `select`, rule 5 checks each model's window against the delegate's last call, `B + K * (S_in + S_out)` with the task's expected sizes (that call reads B + K * S_in + (K - 1) * S_out and writes S_out), not against the K calls' total, and each candidate's `list_cost`, and its `routing_cost` in `cost_effective`, is the cost of its K calls, `model.cost(K * B + w_in * S_in + w_out * S_out, K * S_out)` with its 5.2 sizes (13.2), so the `cost_effective` primary is still the passing delegate with the lowest `delegate_cost_usd`, and the 13.7 exit-3 table prints that cost. Pricing a model at its last call alone would rank by the wrong mix of input and output price, since the K calls' input grows as K squared and their output as K. With K = 1 this is the v1.34 `select`, run as v1.34 runs it. One way for K > 1 is a private `Router` subclass whose candidates are checked and priced this way; `router.stats` and `router.tasks` are the same after the call

### 13.4 Is inline allowed?
The first rule that applies blocks inline (the parent must delegate) and becomes the reason:
1. the parent's family is in `task.exclude_families`: `parent_excluded_family`
2. `task.independent_of_generator`, `generator_model` is given, and the parent is that model or in its family: `parent_not_independent` (the parent cannot check its own family's output)
3. `P.context_window < C + K * (S_in + S_out)`, with the task's expected S_in and S_out whatever the parent's measured sizes (v1.33, as 5.2 rule 5): `parent_context_full`. The last of the K work calls (v1.38) reads C + K * S_in + (K - 1) * S_out and writes S_out, folded or not; K = 1 gives the v1.37 check C + S_in + S_out

The parent clears the bar when its measured trials on the task are at least `task.min_samples` and `parent_quality_lb = wilson_lower_bound(successes, trials, task.confidence)` is at least `task.bar`: the admission test of 5.2 rules 6 and 7. `parent_quality_lb` is 0.0 when the parent is unmeasured; the parent is measured when it has `trials > 0`, as in 5.3

### 13.5 Choosing (the first row that applies wins)
1. Inline blocked: delegate, with the blocking reason and `below_bar = route.below_bar`. With no route, raise `NoModelClearsBar`
2. The delegate clears the bar and the parent does not: delegate, `parent_below_bar`
3. Both clear, `cost_effective`: delegate when `delegate_cost_usd < inline_cost_usd` (`delegate_cheaper`); inline when it is greater (`inline_cheaper`); on an exact tie, delegate when `delegate_quality_lb > parent_quality_lb` (`delegate_better`), else inline (`inline_as_good`)
4. Both clear, `cost_blind`: delegate when `delegate_quality_lb > parent_quality_lb` (`delegate_better`), else inline (`inline_as_good`). Cost is not compared
5. Only the parent clears: inline, `only_parent_clears`
6. Neither clears and `task.on_no_model` is `"refuse"`: raise `NoModelClearsBar`
7. Neither clears and `task.on_no_model` is `"best_available"`: reason `none_clear`, `below_bar` True. Delegate when `route is not None and route.basis == "measured" and (parent unmeasured or delegate_quality_lb > parent_quality_lb)`; else, in `cost_effective` (v1.31), delegate when `route is not None and route.basis == "measured"`, the parent is measured, `delegate_quality_lb == parent_quality_lb` and `delegate_cost_usd < inline_cost_usd`; else inline when the parent is measured; else delegate when there is a route (its basis is `prior`); else raise `NoModelClearsBar`
- `below_bar` is False in rows 2 to 5. A raised `NoModelClearsBar` carries the `.candidates` of the failed `select`
- Costs and bounds are compared with plain `<`, `>` and `==` on the floats as computed, never with a tolerance, so two costs that differ only by rounding are not a tie
- Equal-quality ties go inline in `cost_blind` (rows 4 and 7) and, in `cost_effective`, on an exact cost tie (an exact cost tie in row 3 is settled by the bounds first), because a hand-off has costs the model does not price: a brief can drop detail, and the parent has to trust a result it did not produce. In `cost_effective` a strictly lower `delegate_cost_usd` delegates in row 3 whatever the bounds, and in row 7 when the bounds are equal (v1.31)
- A model below the bar is chosen only under `best_available`, in row 1 or row 7, and then `below_bar` is True
- v1.31: row 7 orders the two paths as 5.3 orders the `best_available` fallback, by bound first and then, in `cost_effective` only, by the path's list-price cost (13.2), so a measured delegate whose bound equals a measured parent's and whose `delegate_cost_usd` is strictly lower is taken. The usual case is the parent's own model as the delegate (its bound is the parent's, from the same stats), where delegating saves the separate inline call's re-read of C (13.2). The costs are compared as computed (no tolerance, as above), so a delegate path that is cheaper only by rounding is taken. With a measured parent, `cost_blind`, an exact cost tie, a lower delegate bound and a `prior` route stay inline; an unmeasured parent still delegates to any route, as before. The reason is `none_clear` in every branch of row 7, so no reason code is added (13.6)
- Row 5 has no equal-model case: a parent that clears in 13.4 reaches 5.2 rule 8 (`passes`) in the delegate's `select` unless rules 1 to 5 stop it, since rules 6 and 7 read the same stats, bar, confidence and `min_samples`, and one passing candidate makes the route clear the bar. So when the route is below the bar, the parent was stopped there by rule 1 (it is in `exclude_models`) or rule 5 (its window holds C + S_in + S_out but not S_in + B + S_out); rules 2 to 4 are the 13.4 blocks that send the decision to row 1. Row 5 stays inline in both flavors, since its delegate does not clear the bar and the parent does; that includes a different delegate whose bound equals or exceeds the parent's but that has too few trials (5.2 rule 6)

### 13.9 Offline delegation evidence (`delegation_eval.py`, v1.19)
Purpose: show from a public outcome matrix, with no API key, what the 13.5 decision does on items it never saw, next to always working inline and always delegating. No public dataset records inline-versus-sub-agent outcomes, so the method combines what a matrix does measure, each model's acceptance and token counts on each item, with a stated grid for what it does not, the parent's context and the hand-off sizes. The decision comes from `Router.decide_delegation`, so the evidence exercises the shipped rules of 13.2 to 13.5 and not a re-implementation of them. The task it builds excludes no family and names no generator, so of the 13.4 blocks only `parent_context_full` can apply here
- `evaluate_delegation(rows, registry, bars, points, seeds=range(10), flavors=("cost_effective", "cost_blind"), parents=None, calibration_fraction=0.5, min_samples=30, confidence=0.95) -> dict`
- `rows`: dicts with `task`, `item`, `model` and `correct` as in 12.1, and `input_tokens` and `output_tokens`, integers `>= 0` that are not bools, required even when `cost_usd` is present. `cost_usd` and other extra keys are ignored: every cost here is a list price from `registry.get(model).cost(...)` (4.1), because the delegate path (13.2) charges one item's tokens to two models, which a billed per-call total cannot be split into
- `registry`: holds every model in the rows; its prices, families and context windows are the ones 13.2 to 13.4 use
- `points`: the grid of assumed sizes, a non-empty sequence of dicts, each with exactly the keys `context_tokens` (C), `brief_tokens` (B), `result_tokens` (R) and `carry_turns` (T), each an integer `>= 0` that is not a bool, and `inline_separate_call`, a bool (13.1), and from v1.43 optionally `work_calls` (K, 13.1), an integer `>= 1` that is not a bool. A point without `work_calls` means K = 1; any other key is still an extra key. A point's values are checked in that key order, so `work_calls` after `inline_separate_call`, and an invalid `work_calls` is a `ValueError` whose message starts `'work_calls' must be an integer >= 1`. Points are compared with a missing `work_calls` read as 1, so a point with `work_calls` 1 and the same point without the key are a repeated point
- `parents`: the model IDs tried as the parent, in the order given; `None` means every model in the rows, ascending
- Checked before any work, each a `ValueError`: no rows; a row that is not a dict, or whose `task`, `item`, `model` or `correct` is invalid as in 12.1, or whose `input_tokens` or `output_tokens` is missing or invalid; a repeated (task, item, model); a model not in `registry`; an incomplete matrix (12.3); bars, seeds and flavors as in 12.3; no points, a point that is not a dict, has a missing or an extra key or an invalid value, or a repeated point; an empty `parents`, a parent that is not a model of the rows, or a repeated parent; `min_samples`, `confidence` and `calibration_fraction` as in 12.3; an empty calibration or held-out split (12.3)
- One **cell** per (bar, flavor, point, parent, seed, task), nested in that order: bars, flavors, points and parents in the order given, seeds in the order given, tasks ascending. C and H are the task's calibration and held-out items from `split_items` (12.2), so a seed splits a task exactly as `evaluate` does
- The decision uses the calibration half only:
  - stats: for each model, successes = its correct rows in C and trials = |C|, and (v1.35) its token totals over those |C| calls, `Stats.add(task, model, successes, |C|, input_tokens=<the sum of its input_tokens over C>, output_tokens=<the sum of its output_tokens over C>)` with the default `token_trials` (4.3). So `decide_delegation` prices the parent, every candidate of the delegate's `select` and the delegate each at that model's own rounded-up mean calibration sizes (13.2, 13.3). Before v1.35 the stats held counts alone and every model was priced at S_in and S_out
  - S_in and S_out: `statistics.median_low` of `input_tokens`, and of `output_tokens`, over the task's calibration rows of every model, so an integer. They are the task's expected sizes, and since every model of the matrix has token totals (v1.35) they set no price: they are read only where 13.3 and 13.4 read the task's expected tokens whatever a model's measured sizes, the 13.4 rule 3 inline check `C + S_in + S_out` and the 5.2 rule 5 check of the delegate's `select`, `S_in + B + S_out`; for a point with K work calls (v1.43) they are `C + K * (S_in + S_out)` and the delegate's last call, `B + K * (S_in + S_out)` (13.3, 13.4)
  - the decision is `Router(registry, {task: t}, stats).decide_delegation(task, parent, flavor, **point)` with `t = Task(name=task, bar=bar, min_samples=min_samples, confidence=confidence, independent_of_generator=False, expected_input_tokens=S_in, expected_output_tokens=S_out, on_no_model="best_available", max_fallbacks=0)`, so a point's `work_calls` (v1.43) reaches `decide_delegation` as its `work_calls`, and a point without it leaves the default 1
  - a cell whose decision has no route, because no model passes 5.2 rule 5 for S_in + B + S_out (for K work calls, for the delegate's last call, B + K * (S_in + S_out), v1.43), is a `ValueError` whose message names the task, the parent and the point as `point <index>`. That is also the only case in which this `decide_delegation` raises `NoModelClearsBar`, which becomes the same `ValueError`
- Strategies, scored on H, in this order: `decision` (inline on the parent when `mode` is `inline`, else delegated to the decision's `model`), `inline` (inline on the parent for every item, even where 13.4 blocks it; the cell's `inline_allowed` says whether it could), `delegate` (delegated to `route.primary` for every item)
- Held-out cost of one item i, with in(i, m) and out(i, m) the tokens of model m's row for i, P the parent, D the model that does delegated work, and C, B, R and T from the point; each expression is evaluated left to right in floating point, as in 13.2:
  - inline with `inline_separate_call` True: `P.cost(C + in(i, P), out(i, P)) + (1 + T) * P.cost(in(i, P) + out(i, P), 0)`
  - inline with `inline_separate_call` False: `P.cost(in(i, P), out(i, P)) + T * P.cost(in(i, P) + out(i, P), 0)`
  - delegated: `P.cost(0, B) + D.cost(B + in(i, D), out(i, D)) + (1 + T) * P.cost(B + R, 0)`
  - v1.43, a point with K work calls (13.1): the cost follows the 13.2 K-call expressions with the item's recorded tokens as the sizes of each of the K work calls, S_in = in(i, m) and S_out = out(i, m) for the model m doing the work on that path, and w_in = K(K + 1) / 2 and w_out = K(K - 1) / 2:
    - inline with `inline_separate_call` True: `P.cost(K * C + w_in * in(i, P) + w_out * out(i, P), K * out(i, P)) + (1 + T) * P.cost(K * (in(i, P) + out(i, P)), 0)`
    - inline with `inline_separate_call` False: `P.cost((K - 1) * C + w_in * in(i, P) + w_out * out(i, P), K * out(i, P)) + T * P.cost(K * (in(i, P) + out(i, P)), 0)`
    - delegated: `P.cost(0, B) + D.cost(K * B + w_in * in(i, D) + w_out * out(i, D), K * out(i, D)) + (1 + T) * P.cost(B + R, 0)`
    - every token total is an integer, so with K = 1 (w_in = 1, w_out = 0) each first and second argument of `P.cost` and `D.cost` is the integer of the K = 1 expression above and every held-out cost is the v1.42 one bit for bit; a point without `work_calls` is that case
    - the item's success on each path is still its one recorded answer, so `correct` counts each held-out item once whatever K: whether the K calls succeed together is not measured, and each of the K calls is assumed to read and write what the item's one recorded call did
  - so the decision is made on calibration-half sizes, each model's own mean since v1.35 (the pooled medians before), and is scored on each held-out item's own recorded sizes for the model that did the work, as before: no held-out cost uses a mean or a median
- For each strategy, `correct` = the number of items in H on which its model's row is correct, `success = correct / |H|`, and `cost_usd` = the `math.fsum` of its item costs over H
- Cell keys: `bar`, `flavor`, `point` (the index into `points`), `parent`, `seed`, `task`, `calibration_items`, `held_out_items`, `expected_input_tokens` (S_in), `expected_output_tokens` (S_out), `mode`, `model`, `reason`, `below_bar` and `inline_allowed` from the decision, `delegate` (`route.primary`), then `correct`, `success` and `cost_usd`, each a dict keyed by strategy in strategy order
- Return value keys: `config` (`bars`, `seeds`, `flavors` and `points` as lists in the order given, each point with its keys in the order above (`work_calls` last, and only on a point that has it, so a grid of points without it serialises as before v1.43), `parents` as the list used, `calibration_fraction`, `min_samples`, `confidence`); `tasks` (`{task: {"items": int, "models": [ids ascending]}}`); `cells` in cell order; `summary`, one row per (bar, flavor, point, parent, strategy) in that order, with keys `bar`, `flavor`, `point`, `parent`, `strategy`, `success` (the mean over seeds of that seed's total `correct` over its total held-out items across tasks), `cost_usd` (the mean over seeds of that seed's total held-out cost across tasks), `below_bar_rate` (the fraction of that group's (task, seed) cells whose held-out success is below the bar, strictly: a success equal to the bar is not below it) and `delegate_rate` (for `decision`, the fraction of those cells whose `mode` is `delegate`; `None` for the two baselines)
- Arithmetic and determinism as in 12.3: every success and rate is an integer count over an integer count, every cost total and the sum behind every mean uses `math.fsum`, the same rows in any order give an equal dict, and `json.dumps(result, sort_keys=True)` is byte-identical
- What is measured and what is assumed:
  - measured, from the matrix: whether each model's answer to each item was accepted, and the input and output tokens of that call
  - from the registry: list prices, families and context windows. On public data the prices are recorded list prices, so every cost is a list-price estimate, never a billed cost
  - assumed, the grid: C, B, R, T, `inline_separate_call` and (v1.43) K. No public matrix records a parent's context or a hand-off, so results are stated per point, never pooled across points
  - assumed, quality: the delegate is credited with its recorded answer to the whole item, as if a brief of B tokens carried everything the item needs; the parent is credited with its recorded answer as if C more tokens of context did not change it. Neither a lossy brief nor long-context degradation is measured, and each would lower one path's success. So the results show what the decision rule does under these assumptions, not the quality of a real hand-off
  - the 13.8 limits apply: one call per path unless a point sets `work_calls` (v1.43), with the bar and the success per call, never for the K calls together; and every read at list price (rho = 1.0, no prompt caching)

- `breakeven_table(results, bar, point) -> str` (v1.37): how much held-out success a lossy hand-off may lose, which the 13.9 quality assumption (the brief carries the whole item) leaves unmeasured, as a number from the committed file with no new run. ## 14. Non-goals for v1 (two-way doors, deferred)
- Native vendor SDK adapters (the OpenAI-compatible adapter covers gateways), async execution, streaming
- Learned or contextual routers (per-prompt difficulty prediction); v1 routes per task
- Online drift detection beyond re-calibrating from audited results; budgets and alerts
- Price refresh automation
- In the delegation cost model (13): prompt caching beyond one cached-read ratio on the parent's reads of its context (from v1.41, 13.2), such as cache-write surcharges, cache expiry and discounts on other re-reads, and latency, including the speed-up of parallel sub-agents (multi-call work is costed from v1.38, 13.2)
