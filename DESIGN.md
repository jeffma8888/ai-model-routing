## 1. Problem
- A product or pipeline makes the same kind of model call many times: triage a support ticket, extract invoice fields, write a unit test, grade an answer against a rubric. Each such kind of call is a **task**: a repeated call with an **acceptance check** that says whether one output is right (agreement with a gold label, exact match on extracted fields, generated tests passing, a rubric pass)
- Sending every call of a task to the strongest model wastes money; sending it to the cheapest model silently lowers quality, and nothing in the logs says so
- The fix is to route per task: measure each candidate model's **success rate** against the task's acceptance check on a calibration set, and pick the cheapest model whose measured rate clears the task's bar with statistical confidence, with fallback when a call fails, a log of every attempt, and cost rolled up by any tag
- Judge and eval calls are the first-class use case, because a wrong judge corrupts every decision downstream of it and because a judge must not grade its own family's output (generator isolation, 5.2). Nothing in the routing rules is specific to judging: the library has no notion of a domain beyond a task name, its bar and its acceptance counts

## 2. Two flavors, one algorithm
- `cost_effective`: among models that clear the bar, pick the one with the lowest expected cost per call; ties go to higher quality
- `cost_blind`: identical pipeline, but the router treats token cost as 0, so among models that clear the bar it picks the highest quality. Fallback, monitoring and attribution are unchanged; the log still records list-price cost so spend stays visible
- The flavor changes exactly one thing: the `routing_cost` used to rank candidates

## 4. Data model

### 4.1 Model and Registry (`registry.py`)
- `@dataclass(frozen=True) class Model`: `id: str`, `family: str`, `price_in: float` (USD per 1M input tokens), `price_out: float` (USD per 1M output tokens), `context_window: int`, `aliases: dict[str, str]` (default empty; provider name to that provider's model ID), and from v1.15 `price_valid_until: str | None` (default `None`)
- v1.15 `price_valid_until` is the last day, inclusive, on which the vendor states the list price, as an ISO date string `YYYY-MM-DD` (four, two and two ASCII digits joined by hyphens, naming a day that exists). Any other value, including a `datetime.date` object, another date spelling or an impossible day such as `2026-02-30`, raises `ValueError` at construction. It is kept as a string so `dataclasses.asdict(model)` stays JSON-able and round-trips through `Registry.load`
- v1.15 `Model.price_expired(today) -> bool` is `True` exactly when `price_valid_until` is set and `today` is a later day; on the stated day itself the price is still valid. `today` is a `datetime.date`, and a `datetime.datetime` counts as its own date; any other type raises `TypeError`
- `Model.cost(input_tokens: int, output_tokens: int) -> float` returns `(input_tokens * price_in + output_tokens * price_out) / 1_000_000`
- `class Registry`: `Registry(models: Iterable[Model])`; `Registry.load(path) -> Registry` reads the models.json format (section 9); `.models -> tuple[Model, ...]` in file order; `.get(model_id) -> Model` raises `KeyError` for an unknown ID; duplicate IDs raise `ValueError` at construction
- v1.15 `Registry.load` reads the optional `price_valid_until` key of a row (absent or `null` means `None`; an invalid value raises `ValueError` naming the file, as any invalid row does), and `Registry.expired_prices(today) -> tuple[Model, ...]` returns the models whose `price_expired(today)` is true, in file order

### 4.2 Task (`tasks.py`)
- `@dataclass(frozen=True) class Task` fields and defaults:
  - `name: str`
  - `bar: float` (required, in [0, 1]; the minimum acceptable success rate against the task's acceptance check, for a judge its agreement with gold labels)
  - `min_samples: int = 30` (fewer measured trials than this can never clear the bar)
  - `confidence: float = 0.95`
  - `independent_of_generator: bool = True` (exclude the generator's model AND its family when the caller names a `generator_model`; no effect otherwise)
  - `exclude_families: tuple[str, ...] = ()`
  - `expected_input_tokens: int = 1000`, `expected_output_tokens: int = 200`
  - `on_no_model: str = "refuse"` (or `"best_available"`)
  - `max_fallbacks: int = 2`
  - `prior_category: str | None = None`
  - `timeout_s: float = 60.0`
- Invalid values raise `ValueError` at construction: bar outside [0, 1], `min_samples < 1`, confidence outside (0, 1), unknown `on_no_model`, negative token counts or `max_fallbacks`
- `load_tasks(path) -> dict[str, Task]` reads `{"tasks": [ {field: value, ...}, ... ]}`; JSON lists become tuples; duplicate names raise `ValueError`

### 4.3 Quality statistics (`stats.py`)
- `wilson_lower_bound(successes: int, trials: int, confidence: float = 0.95) -> float`
  - z = `NormalDist().inv_cdf(1 - (1 - confidence) / 2)` (two-sided interval, lower end); p = successes / trials
  - LB = `(p + z*z/(2n) - z*sqrt(p*(1-p)/n + z*z/(4n*n))) / (1 + z*z/n)`, clamped to `>= 0.0`
  - returns `0.0` when `trials == 0`; raises `ValueError` when `successes < 0`, `trials < 0` or `successes > trials`
  - reference values at confidence 0.95 (to 6 decimals): (27, 30) 0.743789; (45, 50) 0.786398; (90, 100) 0.825634; (170, 200) 0.793944; (10, 10) 0.722467; (0, 10) 0.0
- `class Stats`: in-memory map from `(task, model_id)` to `(successes, trials)`
  - `Stats()`; `.get(task, model_id) -> tuple[int, int]` returns `(0, 0)` when absent; `.add(task, model_id, successes, trials)` accumulates (adds to existing counts) and validates like `wilson_lower_bound`
  - `Stats.load(path)` and `.save(path)` use `{"stats": [{"task": ..., "model": ..., "successes": int, "trials": int}, ...]}`; save writes rows sorted by (task, model)
  - `.merge(other: Stats) -> Stats` returns a new Stats with summed counts
- `calibrate_from_results(rows: Iterable[dict]) -> Stats`: each row has `task`, `model`, and either `correct` (bool) or both `prediction` and `gold` (correct when equal with `==`); a row with neither raises `ValueError`. Each row is one trial
- v1.1 validation: `correct` must be a real boolean (`type(correct) is bool`); a string such as `"false"`, a number or null raises `ValueError`. A row that is not a dict raises `ValueError`. `Stats.load` requires `successes` and `trials` to be integers that are not booleans (`isinstance(v, int) and not isinstance(v, bool)`); floats such as `30.9`, strings and booleans raise `ValueError`, never truncation

### 4.4 Priors (`priors.py`)
- Leaderboard numbers are not agreement rates, so priors NEVER clear a bar. They only order candidates when nothing has been measured (cold start) and tell you which models to calibrate first
- `Priors.load(path)` reads `{"categories": {name: {"metric": str, "source": str, "as_of": str, "scores": {model_id: number}}}}`; `Priors(categories: dict)` takes the same inner dict
- `.score(category, model_id) -> float | None`; unknown category or model returns `None`
- `.ranked(category) -> list[str]` model IDs by descending score, ties by ascending ID

## 5. Routing (`router.py`)

### 5.1 Types
- Reason codes (module constants with these exact string values): `EXCLUDED_MODEL = "excluded_model"`, `EXCLUDED_FAMILY = "excluded_family"`, `GENERATOR = "generator"`, `GENERATOR_FAMILY = "generator_family"`, `CONTEXT_TOO_SMALL = "context_too_small"`, `INSUFFICIENT_SAMPLES = "insufficient_samples"`, `BELOW_BAR = "below_bar"`, `PASSES = "passes"`
- `@dataclass(frozen=True) class Candidate`: `model_id`, `family`, `successes`, `trials`, `quality_lb: float`, `routing_cost: float`, `list_cost: float`, `eligible: bool`, `passes: bool`, `reason: str`
- `@dataclass(frozen=True) class RouteDecision`: `task: str`, `flavor: str`, `primary: str`, `fallbacks: tuple[str, ...]`, `below_bar: bool`, `basis: str` (`"measured"` or `"prior"`), `candidates: tuple[Candidate, ...]` (one per registry model, registry order); `.to_dict()` returns plain JSON-able types (tuples become lists, candidates become dicts)
- `class NoModelClearsBar(Exception)` with attribute `.candidates` (the tuple above)
- Flavor names: `"cost_effective"`, `"cost_blind"`; anything else raises `ValueError`

### 5.2 `Router(registry, tasks: dict[str, Task], stats: Stats, priors: Priors | None = None)`
The constructor stores its arguments as attributes `.registry`, `.tasks`, `.stats`, `.priors`.
`.select(task_name, flavor="cost_effective", generator_model=None, exclude_models=()) -> RouteDecision`; unknown task raises `KeyError`. Steps, in order, per registry model (the first rule that applies sets `reason`):
1. ID in `exclude_models`: `excluded_model`
2. family in `task.exclude_families`: `excluded_family`
3. `independent_of_generator` and ID equals `generator_model`: `generator`
4. `independent_of_generator` and family equals the generator's family (generator looked up in the registry; an unknown generator ID raises `KeyError`): `generator_family`
5. `context_window < expected_input_tokens + expected_output_tokens`: `context_too_small`
6. measured `trials < task.min_samples`: `insufficient_samples` (still eligible for the cold-start path below)
7. `wilson_lower_bound(successes, trials, task.confidence) < task.bar`: `below_bar`
8. otherwise `passes`
- `eligible` is True for reasons 6 to 8; `passes` only for 8
- `list_cost = model.cost(expected_input_tokens, expected_output_tokens)`; `routing_cost = list_cost` for `cost_effective`, `0.0` for `cost_blind`
- `quality_lb = wilson_lower_bound(successes, trials, confidence)` for every candidate (0.0 when unmeasured)

### 5.3 Choosing
- If any candidate passes: sort passing candidates by `(routing_cost, -quality_lb, model_id)`; `primary` is the first; `fallbacks` are the next `max_fallbacks`; `below_bar=False`; `basis="measured"`
- Else if `on_no_model == "refuse"`: raise `NoModelClearsBar`
- Else (`best_available`): among eligible candidates with `trials > 0`, sort by `(-quality_lb, routing_cost, model_id)`; if that list is non-empty use it (`basis="measured"`); otherwise, if the router has priors and the task has `prior_category`, use eligible candidates that have a prior score, sorted by `(-score, routing_cost, model_id)` (`basis="prior"`); `primary` is the first, `fallbacks` the next `max_fallbacks`, `below_bar=True`; if both lists are empty raise `NoModelClearsBar`
- Note: in `cost_blind` the passing sort reduces to `(-quality_lb, model_id)`, so the best measured model wins

## 6. Providers (`providers.py`)
- `@dataclass(frozen=True) class Completion`: `text: str`, `input_tokens: int`, `output_tokens: int`
- `class ProviderError(Exception)`: any failure a fallback should handle (timeout, rate limit, 5xx, bad response)
- `class Provider(Protocol)`: `complete(self, model_id: str, messages: list[dict], timeout_s: float) -> Completion`
- `FakeProvider(script: dict[str, Callable[[list[dict]], Completion]])`: calls `script[model_id](messages)`; an exception raised by the callable propagates unchanged; a model ID not in the script raises `ProviderError`. `.calls` is a list of `(model_id, messages)` in call order
- `OpenAICompatibleProvider(base_url: str, api_key_env: str = "OPENAI_API_KEY", model_map: dict[str, str] | None = None)`: POSTs `{"model": mapped_id, "messages": messages}` to the endpoint `base_url.rstrip("/") + "/chat/completions"`; v1.1: when `base_url` has a query string (for example `?api-version=...`), `/chat/completions` is appended to the path and the query is kept after it (`https://h/v1?q=1` posts to `https://h/v1/chat/completions?q=1`) with `Authorization: Bearer <key>` via `urllib.request`, reads `choices[0].message.content` and `usage.prompt_tokens` / `usage.completion_tokens`; any network, HTTP or parse failure raises `ProviderError`. v1.1 redaction: no `ProviderError` the adapter raises may contain the API key value in `str()`, `repr()` or its exception chain; the adapter replaces every occurrence of the key with `[redacted]` in the message and raises with `from None`; every URL anywhere in a message, including URLs inside text taken from the opener's exception, the HTTP reason and the HTTP body, is shown without userinfo, query string or fragment (`scheme://host[:port]/path`); in addition the password and every query parameter value of `base_url` that is at least 8 characters long, in both its raw form as written in `base_url` (percent escapes and `+` intact) and its decoded form, are replaced with `[redacted]` wherever they appear on their own (the password likewise in both forms) (shorter values such as `v=1` or `beta=true` cannot carry a credential and would only mangle the message; the API key is redacted whatever its length), so credentials embedded in `base_url` never reach a message or a log. If formatting the underlying exception or its HTTP reason itself raises, the adapter still raises `ProviderError` (naming only the exception class) and nothing from the failed formatting leaks. The constructor raises `ValueError` for a `base_url` that is not an `http` or `https` URL with a host, and that message never contains the URL (no `__cause__`, `__suppress_context__` True). For an `urllib.error.HTTPError` the message includes the status code and at most the first 200 characters of the response body, after redaction, and the error has attribute `.status` (int, else `None` on non-HTTP failures). `timeout_s` is passed to the opener and bounds each blocking socket operation (urllib semantics), not the total call. Works with any OpenAI-compatible endpoint (vendor APIs, gateways, local servers). Tests must not touch the network: it accepts an optional `opener` callable (default `urllib.request.urlopen`) for injection

## 7. Execution with fallback (`executor.py`)
- `@dataclass(frozen=True) class Attempt`: `model: str`, `outcome: str` (`"ok"`, `"error"` or `"invalid"`), `error: str | None` (exception class name and message for errors, `"validation failed"` for invalid), `latency_ms: float`, `input_tokens: int`, `output_tokens: int`, `cost_usd: float`
- `@dataclass(frozen=True) class CallResult`: `call_id: str`, `text: str`, `model: str`, `attempts: tuple[Attempt, ...]`, `decision: RouteDecision`
- `class AllModelsFailed(Exception)` with `.attempts` and `.decision`
- `Executor(router, provider, monitor=None, clock=time.monotonic, now=None, id_factory=None)`; `now` returns an ISO 8601 UTC string (default: current UTC time); `id_factory` returns a call ID (default: `uuid.uuid4().hex`)
- `.call(task_name, messages, flavor="cost_effective", generator_model=None, exclude_models=(), tags=None, validate=None) -> CallResult`
  1. `decision = router.select(...)` (its exceptions propagate)
  2. for each model in `(primary, *fallbacks)`: time `provider.complete(model, messages, task.timeout_s)` with `clock`
     - `ProviderError` raised: attempt outcome `error`, tokens 0, cost 0.0; continue. Any other exception propagates (it is a bug, not an outage)
     - `validate` given and `validate(text)` is falsy: outcome `invalid`, tokens and cost from the completion; continue
     - otherwise: outcome `ok`; stop
  3. every attempt is passed to `monitor.record(...)` (when a monitor is given) as it happens, using the record schema in 8.1
  4. no `ok` attempt: raise `AllModelsFailed`
- `cost_usd` of an attempt is the list-price cost of its actual tokens: `registry.get(model).cost(input_tokens, output_tokens)`
- Helper `json_validator(*required_keys) -> Callable[[str], bool]`: True when the text parses as a JSON object containing every key
- v1.11: `.call_delegated(decision, messages, tags=None, validate=None) -> CallResult` runs the hand-off of a `DelegationDecision` (13.6) whose `mode` is `"delegate"`. `messages` is the brief the parent wrote. Steps 2 to 4 of `.call` run over `(decision.route.primary, *decision.route.fallbacks)` with the `timeout_s` of the task named `decision.task` in this executor's router (an unknown task raises `KeyError`), and `CallResult.decision` and `AllModelsFailed.decision` are `decision.route`. The route is used as decided: `select` is not called again, so a stats change after the decision does not move the call
  - Every record's `flavor`, `below_bar` and `basis` come from `decision.route`, and its `tags` are the caller's tags plus `"delegated": "true"` and `"parent": decision.parent`, so `report --by tag:delegated` and `--by tag:parent` split the spend. The caller's dict is not modified
  - `ValueError`, raised before any provider call and any record: a decision whose `mode` is not `"delegate"` (inline work happens in the parent's own call, so there is nothing to run), a `delegate` decision whose `route` is `None` (one built by hand; `decide_delegation` never returns one), and a caller tag named `delegated` or `parent`
  - `.call` is unchanged: it still looks its task up under the caller's `task_name` and names that key in `AllModelsFailed`, after `select` and before `id_factory` and the first provider call
  - The records cover the delegate's calls only. The parent's share of `delegate_cost_usd` (writing the brief, re-reading it and the result, 13.2) is spent in the parent's own calls, which this executor does not see

## 8. Monitoring and cost attribution (`monitor.py`)

### 8.1 Record schema (one JSON object per attempt)
`ts` (str), `call_id` (str), `task` (str), `flavor` (str), `model` (str), `family` (str), `attempt` (int, 0-based index within the call), `final` (bool, True on the call's last attempt), `outcome` (str), `error` (str or null), `latency_ms` (float), `input_tokens` (int), `output_tokens` (int), `cost_usd` (float, list price, recorded in both flavors), `routing_cost_usd` (float: equals `cost_usd` in `cost_effective`, `0.0` in `cost_blind`), `below_bar` (bool), `basis` (str), `tags` (object of string to string; `{}` when none; v1.11: `call_delegated` adds `delegated` and `parent`, 7)

### 8.2 `Monitor(path=None)`
- `.record(rec: dict)` appends to `.records` (a list) and, when `path` is set, appends one JSON line to that file
- `load_records(path) -> list[dict]` reads a JSONL file, skipping blank lines. v1.1: a non-blank line that is not valid JSON, or is valid JSON but not an object, raises `ValueError` whose message contains the path and the 1-based line number (for example `calls.jsonl:3`)

### 8.3 `report(records, by="model") -> list[dict]`
- `by` is `"model"`, `"task"`, `"flavor"`, `"family"`, or `"tag:<key>"` (records without that tag group under `"(none)"`); anything else raises `ValueError`
- Attempt-level sums per group use each attempt's own value: `attempts`, `ok`, `errors`, `invalid`, `input_tokens`, `output_tokens`, `cost_usd`, `routing_cost_usd` (costs rounded to 6 decimals)
- Call-level metrics use the call's FINAL attempt to pick the group: `calls` (calls whose final attempt is in the group), `failed_calls` (final outcome not ok), `fallback_calls` (final attempt index > 0), `fallback_rate` (`fallback_calls / calls`, 0.0 when no calls)
- `p50_latency_ms`, `p95_latency_ms`: nearest-rank percentile over the group's `ok` attempts (sorted ascending, index `ceil(q * n) - 1`), `None` when there are none
- Each row is a dict with key `group` plus the keys above; rows sorted by descending `cost_usd`, then `group`

## 9. Data files
- `model_routing/data/models.json`: `{"version": str, "as_of": "YYYY-MM-DD", "currency": "USD", "models": [{"id", "family", "price_in", "price_out", "context_window", "source"}]}`; IDs are provider-neutral (`vendor/model-name`); map them to a provider's IDs with `aliases`; extra keys such as `notes` are allowed and ignored by `Registry.load`; `aliases` is optional; v1.15: `price_valid_until` is optional (format in 4.1) and is set on a row whose vendor page states an end date for the price, such as a promotional rate (the packaged `openai/gpt-5.6-sol` row: `2026-11-21`)
- `model_routing/data/priors.json`: format in 4.4; each category cites one public leaderboard with its date
- `model_routing/data/example_tasks.json`: three judge tasks (`faithfulness_judge`, `code_correctness_judge`, `pairwise_preference_judge`) whose generator-independence and bars are realistic, and, from v1.2, three non-judge tasks from different domains that check no other model's output and set `independent_of_generator` to `false` to document that intent: `support_ticket_triage` (classification), `invoice_field_extraction` (structured extraction) and `unit_test_codegen` (code generation, accepted when the generated tests pass). For `invoice_field_extraction` an item is accepted only when every field matches exactly, which is why its bar is 0.95. `support_ticket_triage` uses `professional_writing` as the closest packaged prior; priors only order cold-start candidates (4.4). Every packaged task routes in both flavors against the packaged registry once its candidates have passing stats

## 10. CLI (`model-routing`, entry point `model_routing.cli:main(argv=None, *, today=None) -> int`)
- `select TASK [--flavor cost_effective|cost_blind] [--generator MODEL] [--exclude MODEL ...] [--registry PATH] [--tasks PATH] [--stats PATH] [--priors PATH] [--json]`
  - prints primary, fallbacks, basis, below_bar and a candidate table; `--json` prints `RouteDecision.to_dict()`
- `calibrate --results PATH --stats PATH`: reads results JSONL (section 4.3 rows), merges into the stats file (created if missing), prints per (task, model) counts and lower bounds
- `report --log PATH [--by KEY] [--json]`
- `demo [--out DIR]`: runs `run_demo` and prints its summary (v1.12: the inline-or-sub-agent lines are pinned in 11)
- `evaluate --outcomes PATH ...` (v1.3): offline evaluation; options, output and exit codes in 12.4
- `delegate TASK --parent MODEL ...` (v1.4): inline or sub-agent for one piece of work; options, output and exit codes in 13.7
- Defaults: `--registry` and `--priors` and `--tasks` point at the packaged files under `model_routing.DATA_DIR`; `--stats stats.json` in the current directory (a missing stats file means empty stats; a missing priors file means no priors)
- Exit codes: 0 success; 2 bad input (missing file, bad JSON, unknown task or model, invalid value); 3 `NoModelClearsBar` on `select` and `delegate`
- v1.1: every `--exclude` ID and the `--generator` ID must exist in the loaded registry, else exit 2; `calibrate` validates every result row before writing, so bad input leaves an existing stats file byte-identical and creates no new one
- v1.15 price expiry warnings: once `select` or `delegate` has printed its decision (exit 0) or the candidate table of `NoModelClearsBar` (exit 3), it prints on stderr, after all its other output, one line for each model in `Registry.expired_prices(today)` of the loaded registry, in file order: `warning: list price of MODEL was stated valid through YYYY-MM-DD; check the vendor page and update the registry`. ## 12. Offline evaluation (`evaluate.py`, v1.3)
Purpose: show from a public outcome matrix, with no API key, whether routing at a bar holds that bar on items it never saw, and what it costs next to simple baselines. The evaluator routes through `Router.select`, so the evidence exercises the shipped rules (min_samples, the Wilson admission rule, the 5.3 sort keys) and not a re-implementation of them.

### 12.1 Outcome matrix
- JSONL, one object per (task, item, model): `task` (str), `item` (str), `model` (str), `correct` (bool, strict as in 4.3), and the cost of that one call as either `cost_usd` (an int or float that is not a bool, finite and `>= 0`) or both `input_tokens` and `output_tokens` (integers `>= 0` that are not bools), priced with `registry.get(model).cost(input_tokens, output_tokens)`. When `cost_usd` is present it is used and token counts are ignored. Extra keys are ignored
- `@dataclass(frozen=True) class Outcome`: `task: str`, `item: str`, `model: str`, `correct: bool`, `cost_usd: float`
- `outcomes_from_rows(rows: Iterable[dict], registry: Registry | None = None) -> tuple[Outcome, ...]`, in input order. `ValueError` for: a row that is not a dict; `task`, `item` or `model` missing or not a non-empty string; `correct` missing or not a bool; neither `cost_usd` nor both token counts; an invalid cost or token value; a token-form row when `registry` is `None` or does not contain the model; a repeated (task, item, model)
- `load_outcomes(path, registry: Registry | None = None) -> tuple[Outcome, ...]` reads JSONL and skips blank lines; a non-blank line that is not valid JSON, or is not an object, raises `ValueError` whose message contains `<path>:<line>` (1-based) as in 8.2; rows are then validated as above

### 12.2 Split
- `split_items(items: Iterable[str], seed: int, calibration_fraction: float = 0.5) -> tuple[tuple[str, ...], tuple[str, ...]]` returns `(calibration, held_out)`, each sorted ascending with duplicates collapsed. An item is in calibration exactly when `int.from_bytes(hashlib.sha256(f"{seed}:{item}".encode("utf-8")).digest()[:8], "big") < calibration_fraction * 2**64`; otherwise it is held out. The split depends only on the seed and the item ID, so it is the same on every machine and for every row order
- `calibration_fraction` outside the open interval (0, 1) raises `ValueError`

### 12.3 `evaluate(outcomes, bars, seeds=range(10), flavors=("cost_effective", "cost_blind"), calibration_fraction=0.5, min_samples=30, confidence=0.95) -> dict`
- Checked before any work, each a `ValueError`: no outcomes; no bars, a bar that is a bool, not an int or float, not finite (so NaN is rejected) or outside [0, 1], or a repeated bar; no seeds, a seed that is a bool or not an int, or a repeated seed; no flavors, a name not in 5.1, or a repeated flavor; `min_samples < 1`; confidence outside (0, 1); `calibration_fraction` as in 12.2; an incomplete matrix (every model that appears anywhere must have a row for every (task, item) pair that appears anywhere; the message names one missing (task, item, model)); a (task, seed) whose calibration or held-out split is empty (the message names the task and the seed)
- The empty-split rule is deliberately strict: a task with very few items would otherwise be scored on a handful of items in some seeds and not at all in others. When it trips, drop or enlarge that task, use fewer seeds, or move `calibration_fraction` toward 0.5
- One **cell** per (bar, flavor, seed, task), nested in that order: bars, flavors and seeds in the order given, tasks ascending. In a cell, C and H are the task's calibration and held-out items from `split_items(task_items, seed, calibration_fraction)`
  - calibration counts per model: successes = correct rows in C, trials = |C|; mean calibration cost = total cost over C divided by |C|
  - `routed`: the primary of `Router.select(task, flavor)` for a task with this `bar`, `min_samples` and `confidence` and `on_no_model="best_available"`, over a registry in which each model's list cost per call equals its mean calibration cost (so `cost_effective` ranks by measured cost) and no model is excluded by rules 1 to 5 of 5.2. `cleared` is `not decision.below_bar`
  - `cheapest`: the model with the lowest mean calibration cost, ties by model ID
  - `best_on_calibration`: the model with the highest calibration success rate, ties by lower mean calibration cost, then model ID (no bar and no confidence bound)
  - `oracle`: on each held-out item it is correct when any model is correct, and its cost is the lowest cost among the correct models on that item, or the lowest cost among all models when none is correct
  - `model:<id>` for every model in the matrix: that model on every held-out item
  - for every strategy, `success` = correct held-out items / |H| and `cost_usd` = total cost over H
- Strategy order everywhere: `routed`, `oracle`, `best_on_calibration`, `cheapest`, then `model:<id>` by ascending ID
- Cell keys: `bar`, `flavor`, `seed`, `task`, `calibration_items` (int), `held_out_items` (int), `cleared` (bool), `models` (`{"routed": id, "best_on_calibration": id, "cheapest": id}`), and `success` and `cost_usd`, each a dict keyed by strategy name in strategy order
- Return value keys:
  - `config`: `bars`, `seeds` and `flavors` (lists, in the order given), `calibration_fraction`, `min_samples`, `confidence`
  - `tasks`: `{task: {"items": int, "models": [ids ascending]}}`
  - `cells`: the cells above, in cell order
  - `summary`: one row per (bar, flavor, strategy), in that order, with keys `bar`, `flavor`, `strategy`, `success` (mean over seeds of that seed's item-weighted held-out success across all tasks: total correct held-out items / total held-out items), `cost_usd` (mean over seeds of that seed's total held-out cost across all tasks), `below_bar_rate` (fraction of that strategy's (task, seed) cells whose held-out success is below the bar), `cleared_rate` (for `routed`, the fraction of cells with `cleared`) and `bar_violation_rate` (for `routed`, among cleared cells the fraction whose held-out success is below the bar, `None` when no cell cleared); the last two are `None` for every other strategy
  - `per_task`: one row per (bar, flavor, task, strategy), in that order, with the summary keys plus `task` and `routed_models`; `success` and `cost_usd` are means over seeds of that task's cell values, the three rates count that task's cells only, and `routed_models` is `{id: number of seeds routed to it}` for `routed` and `None` otherwise
- Arithmetic: every success rate and every rate is an integer count divided by an integer count (for the summary `success`, total correct held-out items over total held-out items, both integers). Every cost total, and the sum behind every mean, is computed with `math.fsum`, which is exactly rounded and so independent of summation order; a mean is that sum divided by its count
- Granularity: in `summary`, `success` and `cost_usd` weight every held-out item equally within a seed, while `below_bar_rate`, `cleared_rate` and `bar_violation_rate` count (task, seed) cells, so a small task weighs as much as a large one in the rates but not in `success`. `success` above the bar does not imply a zero `below_bar_rate`
- Deterministic: the same outcomes in any row order with the same arguments give an equal dict, and `json.dumps(result, sort_keys=True)` is byte-identical
- Reading the numbers: `wilson_lower_bound` is the lower end of a two-sided interval (4.3), so for one model judged once its nominal chance of admitting a true rate below the bar is about `(1 - confidence) / 2` (2.5% at 0.95), and that figure is approximate because Wilson coverage is not exact. Three things push the observed `bar_violation_rate` above it: the routed model is the cheapest (or best) of several passing models, and that selection favours models whose calibration rate came out high by chance; the held-out rate is itself a noisy estimate, so a model whose true rate sits just above the bar misses it on a small held-out set often; and the seeds are re-splits of one item pool, so cells are correlated rather than independent trials. Read the rate as a resampling estimate for this matrix, next to `(1 - confidence) / 2` and the held-out size, never as a guarantee and never against zero

### 12.4 CLI
- `model-routing evaluate --outcomes PATH [--bar B [B ...]] [--seeds K] [--calibration-fraction F] [--min-samples N] [--confidence C] [--registry PATH] [--json]`

  - v1.5 text layout: for each (bar, flavor) in config order, a heading line `bar <bar>, <flavor>` (the bar as Python `str` prints it), then a table in the layout of the other commands (header, a dash row, one row per strategy in strategy order) with columns `strategy`, `success`, `cost_usd`, `below_bar_rate`, `cleared_rate`, `bar_violation_rate`, built from the `summary` rows; rates and success to 3 decimals, `cost_usd` to 4, `-` for `None`. One blank line between tables and none after the last
  - exit codes: 0 success; 2 bad input (missing or unreadable file, bad JSON, invalid row, incomplete matrix, empty split, invalid option value), with a one-line `error: ...` message on stderr as for the other commands

### 12.6 Public evidence: the RouterBench converter (`evidence/routerbench/convert.py`, v1.6)
Purpose: turn a public dataset that already holds every model's output, correctness and cost per prompt into the 12.1 matrix, so the evaluator runs on third-party data with no API key. It lives outside the package: `model_routing` never imports it, it is standard library except that reading the frame needs pandas (the `evidence` extra), and the tests that need pandas use `pytest.importorskip`, so CI passes without it
- Source, pinned: dataset `withmartian/routerbench` on Hugging Face at revision `784021482c3f320c6619ed4b3bb3b41a21424fcb`, file `routerbench_0shot.pkl`, `SIZE = 99567659` bytes, `SHA256 = "ba4f77f19517610a707c374e99322d7750c30fc4ae7ff5527888595a1e65d36d"` (its LFS object ID). The RouterBench code is MIT licensed (https://github.com/withmartian/routerbench); the dataset card states no data licence, and the evidence README says so
- `default_cache_dir()` is `~/.cache/ai-model-routing-evidence/routerbench/` (from `Path.home()`), never inside the repo. `fetch(cache_dir=None) -> Path`: the file is `cache_dir / "routerbench_0shot.pkl"`. A present file is verified and used, and one that fails `verify` is a `ValueError` naming it and is left in place (delete it to download again); a missing file is downloaded with `urllib.request.urlopen` from `https://huggingface.co/datasets/withmartian/routerbench/resolve/<revision>/routerbench_0shot.pkl` into a `.part` file next to it, verified, then renamed, and the `.part` file is removed when the check fails
- `verify(path, size=SIZE, sha256=SHA256)`: `ValueError` naming the expected and the actual value when the byte size or the sha256 differs. Nothing is unpickled before it passes
- `RestrictedUnpickler(pickle.Unpickler)`, `restricted_load(fileobj)` and `load_frame(path)`; `load_frame` opens the file, runs `restricted_load` and turns any other exception raised while unpickling (an empty or truncated file, an allowed callable given bad arguments) into a `ValueError` naming the file, so only `pickle.UnpicklingError` and `ValueError` leave it. In `restricted_load`, `find_class` resolves only the (module, name) pairs in `ALLOWED_GLOBALS`, exactly the 11 globals the pinned file references (found with a static `pickletools` opcode scan, which runs no code): `builtins.slice`, `numpy.dtype`, `numpy.ndarray`, `numpy.core.multiarray._reconstruct`, `numpy.core.numeric._frombuffer`, `pandas._libs.internals._unpickle_block`, `pandas.core.frame.DataFrame`, `pandas.core.indexes.base.Index`, `pandas.core.indexes.base._new_Index`, `pandas.core.indexes.range.RangeIndex`, `pandas.core.internals.managers.BlockManager`. Any other global raises `pickle.UnpicklingError` naming it, with no module-prefix wildcard; names are checked as written, with no Python 2 name mapping (`fix_imports=False`), and persistent IDs are refused. Because the file is hash-pinned, the list only has to cover that one file; a pickle written by another pandas or numpy version is refused, not trusted
- `model_id(column) -> str`: a column name of the form `vendor/model` (one `/`, both sides non-empty) is kept as is, and any other name containing `/` is a `ValueError`; a name starting `claude-` becomes `anthropic/<name>` and one starting `gpt-` becomes `openai/<name>`; anything else is a `ValueError` rather than a guess
- `frame_columns(frame) -> dict[str, list]`: `ValueError` naming the type when `frame` has no `columns` attribute (a pickle that loads to something other than a frame); otherwise plain Python lists, from `.tolist()`, for `sample_id`, `eval_name` and, for every model column `<m>`, both `<m>` (the score) and `<m>|total_cost`. A model column is any column without `|` other than `sample_id`, `prompt`, `eval_name` and `oracle_model_to_route_to`. Prompts and responses are never read. `ValueError` when `sample_id` or `eval_name` is missing, there is no model column, or a model has no `|total_cost` column
- `convert(columns, pass_score=None, min_items=100) -> tuple[list[dict], dict]`, where `columns` is what `frame_columns` returns (any `dict[str, list]` of that shape):
  - `ValueError`, checked before any output: columns of different lengths; a `sample_id` that is not a non-empty string or is repeated; an `eval_name` that is not a non-empty string; a score that is a bool, not an int or float, NaN or outside [0, 1]; a cost that is a bool, not an int or float, not finite or below 0 (score and cost messages name the `sample_id` and the column); `pass_score` that is not `None` and is a bool, not an int or float, or outside (0, 1] (so NaN is rejected); `min_items` that is a bool, not an int, or below 1; a model column that `model_id` rejects, or two columns mapping to one ID
  - each source row is one item: task = `eval_name`, item = `sample_id`, and one output row per model with model = `model_id(column)`, `cost_usd` = the recorded `total_cost` as a float, with a negative zero written as `0.0`
  - scores and costs must be Python `int` or `float` values (a `float` subclass such as numpy's float64 counts); other numeric types such as numpy's int64 or float32 are rejected, which `.tolist()` never produces but a hand-built `columns` dict could
  - graded tasks: a task is graded when any of its scores, for any model, is not exactly 0 or 1. With `pass_score=None` a graded task is dropped; otherwise it is kept. In a kept task `correct` is `score >= pass_score` when `pass_score` is set and `score == 1` when it is not, which agree on 0 or 1 scores for every allowed `pass_score`. The pinned file's graded tasks (`grade-school-math` with scores in {0, 0.25, 0.5, 0.75, 1}, `consensus_summary`, the `mtbench` tasks, `chinese_idioms`) do not document what a partial score means, so excluding them is the default and including them is the user's stated choice
  - small tasks: a task left with fewer than `min_items` items is dropped. The default 100 gives calibration and held-out halves of about 50 items, so in practice 12.3's empty-split rule does not trip and `min_samples = 30` can be met
  - output rows have the keys `task`, `item`, `model`, `correct`, `cost_usd` in that order, sorted by (task, item, model) as strings; they form the complete matrix 12.3 requires, and the result does not depend on the source row order
  - the report has keys `models` (IDs ascending), `kept`, `dropped_graded` and `dropped_small` (each `{task: number of items}` with tasks ascending) and `rows` (the number of output rows)
- `write_jsonl(rows, path)`: one `json.dumps(row)` per line, newline-terminated, in the given order
- CLI: `python evidence/routerbench/convert.py --out PATH [--cache DIR] [--pass-score T] [--min-items N]`, entry point `main(argv=None) -> int`. Options are checked first (no download for a bad one); then it fetches, verifies, loads with `load_frame`, converts and writes, and prints the report as `json.dumps(report, indent=2)`. It returns 0 on success and 2 with exactly one `error: ...` line on stderr and nothing on stdout for a missing or invalid option, a size or hash mismatch, a refused global, a file that does not unpickle to a frame, invalid data or an I/O error. The matrix is written to `<out>.part` and renamed onto `--out`; on any failure `--out` is not written and `<out>.part` is removed
- Reading it: the 11 models date from 2023 and the costs are the ones the dataset recorded at that time's prices; the evaluator routes per task (an `eval_name`), not per prompt

### 12.7 RouterBench results (`evidence/routerbench/results.py`, v1.7)
Purpose: commit the evaluator's numbers on RouterBench in a file small enough to review, regenerated byte for byte from stated commands, with the tables in `RESULTS.md` checked against it by the test suite. Standard library only: it reads JSON and never imports pandas
- `reduce(result: dict) -> dict`: from an `evaluate` result (12.3, with or without `cells`, so the `evaluate --json` output too), a new dict with the keys `config`, `tasks`, `summary` and `per_task` in that order, where `per_task` keeps only the rows whose `strategy` is `routed`, in their order; `cells` and the other per-task strategies are left out so the file stays under about 300 KB. Values are copied unchanged and the input is not modified, so `reduce(reduce(r)) == reduce(r)`. `ValueError` naming the key when one of the four is missing
- `table(results: dict) -> str`: two tables in the layout of 12.4 (header, a dash row, one row per line, trailing spaces stripped), separated by one blank line, with no newline after the last:
  - routed: one row per (bar, flavor) in config order, from that block's `routed` summary row, with columns `bar` (as Python `str` prints it), `flavor`, `success`, `cost_usd`, `vs_best_model`, `cleared_rate` and `bar_violation_rate`; `vs_best_model` is the routed `cost_usd` divided by the best model's `cost_usd`
  - baselines: from the summary rows of the first (bar, flavor) in config order (held-out success and cost do not depend on the bar or the flavor), one row per strategy other than `routed`, in summary order, with columns `strategy`, `success` and `cost_usd`
  - the best model is the `model:<id>` row of that first block with the highest `success`, ties by lower `cost_usd`, then by strategy name
  - success, rates and `vs_best_model` to 3 decimals, `cost_usd` to 4; `-` for `None`, and for `vs_best_model` when the best model's cost is 0
  - `ValueError` when `config` or `summary` is missing, a (bar, flavor) in the config has no `routed` summary row, or the first block has no `model:` row
- CLI: `python evidence/routerbench/results.py --evaluate PATH --out PATH` writes `json.dumps(reduce(result), indent=2)` and a newline to `--out`, where `result` is the JSON object read from `--evaluate`; `python evidence/routerbench/results.py --table PATH` prints `table(results)` for the JSON object read from `PATH`. Exactly one of `--evaluate` and `--table` is given, and `--out` comes with `--evaluate` and never with `--table`. ## 13. Delegation: inline or sub-agent (`delegation.py`, v1.4; cost accounting v1.8)
Purpose: an agent (the **parent**: a model already running with its own context) reaches a piece of work that is one call of a task. It can do the work itself (**inline**) or hand it to a fresh sub-agent running the model the router picks (**delegate**). The decision weighs what routing weighs, the measured success rate against the task's bar and list-price cost, plus what each path does to the parent's context. The delegate is chosen by `Router.select`, so the 5.2 rules, the Wilson admission rule and both flavors apply unchanged.

### 13.1 Inputs
`Router.decide_delegation(task_name, parent_model, flavor="cost_effective", *, context_tokens, brief_tokens, result_tokens, carry_turns=0, inline_separate_call=True, generator_model=None, exclude_models=()) -> DelegationDecision`
- `parent_model`: the parent's model ID. An unknown task, parent or `generator_model` raises `KeyError`; an unknown flavor raises `ValueError` (5.1)
- `context_tokens` (C): tokens already in the parent's context
- The work is one call of the task: it reads S_in = `task.expected_input_tokens` and writes S_out = `task.expected_output_tokens`
- `brief_tokens` (B): what the parent writes to hand the work off. `result_tokens` (R): what the parent reads back
- `carry_turns` (T): parent calls after the parent's next call (13.2) that still re-read what this work leaves in its context. The next call itself is always charged, so T = 0 means the parent makes one more call after the work and stops. When the work is one of several sibling subtasks that the parent would otherwise do one after another, each later sibling done inline re-reads this one, so those calls count in T
- `inline_separate_call`: True (the default) when inline work takes a parent call of its own, False when the parent folds the work into its next call (13.2). It must be a bool, else `ValueError`
- `generator_model` and `exclude_models` mean what they mean in 5.2 and are passed to the delegate's `select`. `exclude_models` limits the delegate only; it never stops the parent working inline
- `context_tokens`, `brief_tokens`, `result_tokens` and `carry_turns` must be integers `>= 0` that are not bools, else `ValueError`
- The router is not modified: `router.tasks` is the same after the call

### 13.2 Cost of each path (list price, reported in both flavors)
The accounting follows the parent's calls, each of which re-reads the parent's whole context. Both paths are charged for the same calls, and each only for what that path adds to them:
- The **decision turn**, the parent call that makes this decision, happens on both paths. On the delegate path it also writes the brief, so B is charged once as parent output; on the inline path it writes nothing extra. Fetching the work's input is free on both paths; reading it is charged on both
- The parent's **next call** after the work is done (on the delegate path, the call that reads the result) and the T calls after it happen on both paths and re-read C on both, so C is not charged in them. Each of these 1 + T calls is charged for the tokens that the path left in the parent's context. What a call writes besides the work, the parent's own next step, is the same on both paths and is not charged
- The work itself: the delegate reads the brief and the work's input in a fresh context and writes the output. Inline, the parent does it either in a call of its own over its whole context (`inline_separate_call=True`) or inside its next call (`inline_separate_call=False`), which then also reads S_in and writes S_out. A separate call fits work that is a step of its own, for example output that goes into a tool call or a file before the parent goes on; folding fits work the parent would do as part of its very next reply anyway. The default, a separate call, gives the higher inline cost

With P the parent's model and D the delegate:
- `delegate_cost_usd = P.cost(0, B) + D.cost(B + S_in, S_out) + (1 + T) * P.cost(B + R, 0)`: the brief written, the delegate's call, then the brief and the result re-read by the next call and the T after it
- `inline_cost_usd = P.cost(C + S_in, S_out) + (1 + T) * P.cost(S_in + S_out, 0)` when `inline_separate_call` is True: the parent's own call for the work, then its input and output re-read by the next call and the T after it
- `inline_cost_usd = P.cost(S_in, S_out) + T * P.cost(S_in + S_out, 0)` when `inline_separate_call` is False: the next call also reads S_in and writes S_out, and both are re-read by the T calls after it
- C appears only in the separate inline call. With a separate call, inline minus delegating to the parent's own model (D = P) is, in exact arithmetic, `P.cost(C, 0) - P.cost(B, B) + (1 + T) * (P.cost(S_in + S_out, 0) - P.cost(B + R, 0))`, so delegating even to its own model can save in two ways: the separate call's re-read of a large context C (the context-isolation case), and later calls that re-read a short brief and result instead of the work's input and output. When the work folds into the next call, C cancels, and delegating to the parent's own model is cheaper only when `T * P.cost(S_in + S_out, 0)` exceeds `P.cost(B, B) + (1 + T) * P.cost(B + R, 0)`, so never with T = 0
- Each expression is evaluated left to right as written, in floating point, from `Model.cost` (4.1); `1 + T` is an integer. `delegate_cost_usd` is `None` when there is no delegate
- This is still an approximation. It assumes one call per path (13.8), no prompt caching, the same parent output after the work on both paths (checking a delegate's result may take more), and that the parent's later calls fit its context on both paths: C + S_in + S_out is checked for inline (13.4) but C + B + R is not checked for delegate

### 13.3 The delegate
- The delegate is the primary of `Router.select(task_name, flavor, generator_model, exclude_models)` run with the same registry, stats and priors on a copy of the task whose `expected_input_tokens` is `S_in + B`, so the context rule (5.2 rule 5) and the `cost_effective` ranking see the brief the delegate actually reads. It may be the parent's own model
- `route` is that `RouteDecision`, or `None` when that `select` raises `NoModelClearsBar`. `delegate_quality_lb` is the `quality_lb` of the route's primary candidate. The delegate clears the bar when `route.below_bar` is False
- The parent's share of `delegate_cost_usd` is the same for every delegate, so the `cost_effective` primary of this `select` is also the passing delegate with the lowest `delegate_cost_usd`

### 13.4 Is inline allowed?
The first rule that applies blocks inline (the parent must delegate) and becomes the reason:
1. the parent's family is in `task.exclude_families`: `parent_excluded_family`
2. `task.independent_of_generator`, `generator_model` is given, and the parent is that model or in its family: `parent_not_independent` (the parent cannot check its own family's output)
3. `P.context_window < C + S_in + S_out`: `parent_context_full`

The parent clears the bar when its measured trials on the task are at least `task.min_samples` and `parent_quality_lb = wilson_lower_bound(successes, trials, task.confidence)` is at least `task.bar`: the admission test of 5.2 rules 6 and 7. `parent_quality_lb` is 0.0 when the parent is unmeasured; the parent is measured when it has `trials > 0`, as in 5.3

### 13.5 Choosing (the first row that applies wins)
1. Inline blocked: delegate, with the blocking reason and `below_bar = route.below_bar`. With no route, raise `NoModelClearsBar`
2. The delegate clears the bar and the parent does not: delegate, `parent_below_bar`
3. Both clear, `cost_effective`: delegate when `delegate_cost_usd < inline_cost_usd` (`delegate_cheaper`); inline when it is greater (`inline_cheaper`); on an exact tie, delegate when `delegate_quality_lb > parent_quality_lb` (`delegate_better`), else inline (`inline_as_good`)
4. Both clear, `cost_blind`: delegate when `delegate_quality_lb > parent_quality_lb` (`delegate_better`), else inline (`inline_as_good`). Cost is not compared
5. Only the parent clears: inline, `only_parent_clears`
6. Neither clears and `task.on_no_model` is `"refuse"`: raise `NoModelClearsBar`
7. Neither clears and `task.on_no_model` is `"best_available"`: reason `none_clear`, `below_bar` True. Delegate when `route is not None and route.basis == "measured" and (parent unmeasured or delegate_quality_lb > parent_quality_lb)`; else inline when the parent is measured; else delegate when there is a route (its basis is `prior`); else raise `NoModelClearsBar`
- `below_bar` is False in rows 2 to 5. A raised `NoModelClearsBar` carries the `.candidates` of the failed `select`
- Costs and bounds are compared with plain `<`, `>` and `==` on the floats as computed, never with a tolerance, so two costs that differ only by rounding are not a tie
- Equal-quality ties go inline (an exact cost tie in row 3 is settled by the bounds first), because a hand-off has costs the model does not price: a brief can drop detail, and the parent has to trust a result it did not produce
- A model below the bar is chosen only under `best_available`, in row 1 or row 7, and then `below_bar` is True

### 13.6 `DelegationDecision`
- `@dataclass(frozen=True) class DelegationDecision`, fields in this order: `task: str`, `flavor: str`, `parent: str`, `mode: str` (`"inline"` or `"delegate"`), `model: str` (the parent for inline, `route.primary` for delegate), `reason: str`, `below_bar: bool`, `inline_allowed: bool`, `inline_cost_usd: float`, `delegate_cost_usd: float | None`, `parent_quality_lb: float`, `delegate_quality_lb: float | None`, `route: RouteDecision | None`
- `.to_dict()` returns plain JSON-able types, keys in the field order above, with `route` as `route.to_dict()` or `None`
- Module constants with these exact values: `INLINE = "inline"`, `DELEGATE = "delegate"`, and reason codes whose values are their names in lower case: `PARENT_EXCLUDED_FAMILY`, `PARENT_NOT_INDEPENDENT`, `PARENT_CONTEXT_FULL`, `PARENT_BELOW_BAR`, `DELEGATE_CHEAPER`, `INLINE_CHEAPER`, `DELEGATE_BETTER`, `INLINE_AS_GOOD`, `ONLY_PARENT_CLEARS`, `NONE_CLEAR`
- `DelegationDecision` is re-exported from `model_routing` and listed in `__all__`; the constants stay in `model_routing.delegation`
- v1.11: `Executor.call_delegated(decision, messages, ...)` runs a `delegate` decision on its route, with fallback and logging as for any call (7)

### 13.7 CLI
- `model-routing delegate TASK --parent MODEL --context-tokens N --brief-tokens N --result-tokens N [--carry-turns N] [--fold-inline] [--flavor cost_effective|cost_blind] [--generator MODEL] [--exclude MODEL ...] [--registry PATH] [--tasks PATH] [--stats PATH] [--priors PATH] [--json]`, with the defaults of section 10; `--fold-inline` passes `inline_separate_call=False`
- Prints exactly eight lines, one per key in this order, the key, a colon, spaces, then the value: `mode`, `model`, `reason`, `below_bar` (`true` or `false`), `inline_cost_usd` and `delegate_cost_usd` (6 decimals), `parent_quality_lb` and `delegate_quality_lb` (3 decimals); a `None` value prints as `-`. `--json` prints `DelegationDecision.to_dict()`
- Exit codes: 0 success; 2 bad input (as for `select`, plus a `--parent` that is not in the registry and a token option that is not an integer `>= 0`), including a missing required option, with exactly one `error: ...` line on stderr and it is the last line (an argument-parsing error prints the usage first, as for `select`); 3 `NoModelClearsBar`, with the candidate table on stderr as for `select`

## 14. Non-goals for v1 (two-way doors, deferred)
- Native vendor SDK adapters (the OpenAI-compatible adapter covers gateways), async execution, streaming
- Learned or contextual routers (per-prompt difficulty prediction); v1 routes per task
- Online drift detection beyond re-calibrating from audited results; budgets and alerts
- Price refresh automation
- In the delegation cost model (13): multi-call work, prompt-caching discounts, and latency, including the speed-up of parallel sub-agents
