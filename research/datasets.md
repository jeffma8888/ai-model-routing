# Public datasets with per-item outcomes on coding or agentic tasks (as of 2026-11-06)

Question: is there a public dataset, with a stated licence, that holds every model's or agent's outcome per item on a coding or agentic task checked by a program (unit tests, a database state check), ideally with a per-item cost or token counts? The committed evidence uses two datasets, RouterBench (mostly multiple-choice MMLU subjects) and AutoBench 2026 (graded by a committee of model judges), so no committed result comes from such a task yet.

Method: every revision below is the commit or dataset SHA that the GitHub or Hugging Face API returned on 2026-11-06. Licences are as the repo's LICENSE file, the API's licence field or the dataset card states them ("none stated" if absent). Sizes are the API's file sizes. Sample files were downloaded outside the repo and read with the standard-library `json` module; nothing from them is committed.

Model ids below use the provider-neutral form `provider/name`.

A second question, a dataset with many tasks whose best model differs, is answered in [Many-task routing data (2026-11-09)](#many-task-routing-data-2026-11-09) at the end. A third, a seventh routing dataset after LLMRouterBench, is answered in [Seventh routing dataset (2026-11-11)](#seventh-routing-dataset-2026-11-11) after it.

## Summary

- Recommended: the tau2-bench paper results. They are the one candidate found with a stated licence (MIT), a per-item outcome from a program check, and a per-item cost
- Their limits: 4 agent models from 2 providers, all released in 2025, and a model plays the user in every conversation
- LiveCodeBench submissions (MIT, 72 model folders, labels from test cases) have the widest coding pool but no cost or token counts, so they could feed `cost_blind` only
- SWE-bench experiments has the most agents (182 folders for SWE-bench Verified) but no stated licence, so it stays out by the same rule as the two routing datasets at the end

## Candidates

### 1. tau2-bench paper results (recommended)

- URL: https://github.com/sierra-research/tau2-bench, folder `data/tau2/results/final`
- Revision: 033bf082f48e4a3c6a1256208e93cf2ce9c3bb6f (commit date 2026-11-04)
- Licence: MIT (the repo's LICENSE file and the API's licence field)
- Files: 26 run JSON files, 603,837,972 bytes in all; the 12 default runs (4 agent models by 3 domains) are 295,933,742 bytes, from 7,599,444 to 51,038,687 bytes each (also the smallest and largest of the 26)
- Agents: anthropic/claude-3-7-sonnet-20250219, openai/gpt-4.1-2025-04-14, openai/gpt-4.1-mini-2025-04-14 and openai/o4-mini-2025-04-16, all released in 2025. The user simulator is openai/gpt-4.1-2025-04-14 at temperature 0 in every run
- Items: 50 airline tasks, 114 retail and 114 telecom (counted in the o4-mini runs; the claude-3-7-sonnet airline run also has 50), 4 trials per task, so 200, 456 and 456 simulations per run file
- Label: `reward_info.reward`, 0.0 or 1.0 per simulation, from program checks. In airline and retail the reward basis is `DB` and `COMMUNICATE` (the final database state against the expected one, and the values the agent had to tell the user); in telecom it is `ENV_ASSERTION`, plus `ACTION` in 80 of the 456 simulations. No model judge is in the reward basis of the 4 files read
- Cost and tokens: every simulation has `agent_cost` and `user_cost` in USD (200 of 200, 456 of 456 and 456 of 456 in the three o4-mini runs, 200 of 200 in the claude-3-7-sonnet airline run), and the agent's messages carry `usage` with `prompt_tokens` and `completion_tokens`. The files do not say which price table produced `agent_cost`
- Caveat from the folder's README: these are the June 2025 paper results, produced "before the task fixes that shipped in v1.0.0". It goes on: "The airline and retail tasks recorded here therefore differ from the current base tasks, and `tau2 submit` task verification rejects them (airline: 29 tasks differ, retail: 114). Telecom is unchanged and verifies." The runs read have 114 retail tasks, so the README's retail count is the whole retail set. They "are not leaderboard submissions". The leaderboard folder `web/leaderboard/public/submissions` has 88 submission folders (71 with a 2026 date in the name, 12 with 2025, 5 with 2024) beside 7 files at the folder's top level. 77 hold a `submission.json` with pass rates per domain only. The other 11, all dated 2026-10, hold a `benchmark-submission.json` with one reward per (language, domain, task, trial); the one read, ava-zero, is a voice run (mode `voice`; 900 trials, 6 languages by 3 domains, 1 trial each) with no cost or token counts, so these may be a per-item source for 2026 models, but for a voice benchmark and without cost
- Converter: standard-library `json`, so no new dependency under the `evidence` extra. Load one run file at a time (up to 51 MB), keep only (domain, task id, trial, reward, `agent_cost`, summed tokens) and pin each file's sha256. DESIGN 12.1 takes one row per (task, item, model), so either each trial becomes its own item or the converter keeps one trial, and the choice is stated. One routing task per domain gives 4 models by 278 items if one trial is kept, or by 1,112 if each trial is its own item; the converter sizes its committed results file against the about 300 KB cap. None of the four models is in `model_routing/data/models.json`, so the cost is either `agent_cost` as each row's `cost_usd`, or the token counts priced from a dated public price list with `agent_cost` as a cross-check

- URL: https://github.com/LiveCodeBench/submissions
- Revision: 6ca212e9c2039373f6e5069d37ffa9db66e23736 (commit date 2025-08-01; the repo is archived)
- Licence: MIT (the repo's LICENSE file and the API's licence field). The problems come from LeetCode, AtCoder and Codeforces, so a converter keeps only question ids, dates and labels, never question text or generated code

- Cost and tokens: none. `metadata` holds an execution time per sample, and `output_list` holds the raw output, so only a character count of the output is available
- Converter: standard-library `json`; the full download is 1.35 GB, so read file by file and keep (model, question id, contest date, passes, samples). It could feed `cost_blind` only, unless a dated price list and a token estimate are added and stated as assumptions

## Many-task routing data (2026-11-09)

Question: is there a public dataset, with a stated licence, that holds several models' per-item outcomes on many tasks, ideally with a per-item cost or token counts, where the tasks differ in their best model? [routerbench-per-task.md](routerbench-per-task.md) finds that on RouterBench one model is the best, or tied for the best, on every eval, so per-task routing there gains almost nothing in success; its `## What another dataset needs` asks for tasks whose best model leads the best single model by more than the Wilson shortfall at the task's calibration half, holding enough of the items.

Method: revisions are the dataset or commit SHAs the Hugging Face and GitHub APIs returned on 2026-11-09; licences as the card's licence field, a LICENSE file or the API state them. The Hugging Face search API was queried for router, routing, RouterBench, RouterEval, FusionBench, EmbedLLM, LLMRouterBench, RouterArena, SPROUT and RoutingBench. The one file read in full, the LLMRouterBench tarball, was downloaded outside the repo, its sha256 matched the LFS oid the API lists, and a probe outside the repo read it with the standard-library `tarfile` and `json` modules. Nothing from it is committed. The probe joins a folder's files on the record `index` and keeps an item only where a digest of its `origin_query` agrees across the pool's models, which drops 2 items (`arenahard` index 103, `hle` index 1494). Model IDs are this note's provider-neutral form of the folder names.

### 1. LLMRouterBench (recommended)

- URL: https://huggingface.co/datasets/NPULH/LLMRouterBench, file `bench-release.tar.gz`; code and dataset tables at https://github.com/ynulihao/LLMRouterBench; paper arXiv 2601.07206, "LLMRouterBench: A Massive Benchmark and Unified Framework for LLM Routing", submitted 12 Jan 2026
- Revision: b95870f9e60c589e82f7972c91ffa8de9ca89f85 (commit "Add MIT LICENSE", 2026-11-02); the tarball is unchanged since 2025-12-08, 1,283,503,080 bytes, sha256 b79f8cde1a6f029c2efa663a3a3b6f7748defb22341fe59f328cebef6648c8f1. GitHub head 811df08b1b37646064eeb8cb6acfd498bf99885a (2026-11-02, the same commit message)
- Licence: MIT, "Copyright (c) 2025-2026 LLMRouterBench contributors", in a LICENSE file at both revisions, with a scope paragraph: "This license applies to the original code and benchmark data contributions of LLMRouterBench, to the extent of the contributors' rights. Third-party datasets, code, and other incorporated materials retain their original licenses." The GitHub API's licence field reads NOASSERTION, since the file is not the plain MIT text. The card has no licence field. The file was added on 2026-11-02, so the dataset had no stated licence before then
- Files: 700 JSON result files, one per (benchmark folder and split, model folder), over 27 benchmark folders (31 with their splits) and 40 model folders, dated 2025-09-15 to 2025-12-02 in their names. Each holds the run's totals and one record per item with `index`, `origin_query`, `prompt`, `prompt_tokens`, `completion_tokens`, `cost`, `score`, `prediction`, `ground_truth` and `raw_output`
- Pools (the GitHub README's two settings): a performance pool of 20 open models of 7B to 9B parameters, and a performance-cost pool of 13 API models: `anthropic/claude-sonnet-4`, `google/gemini-2.5-flash`, `google/gemini-2.5-pro`, `openai/gpt-5-chat`, `openai/gpt-5`, `qwen/qwen3-235b-a22b-2507`, `qwen/qwen3-235b-a22b-thinking-2507`, `deepseek/deepseek-v3-0324`, `deepseek/deepseek-v3.1-terminus`, `deepseek/deepseek-r1-0528`, `z-ai/glm-4.6`, `moonshotai/kimi-k2-0905` and `internlm/intern-s1`, all released in 2025. The other 7 model folders (among them a commercial router's picks) are in neither pool
- Tasks: the folders `arenahard_coding`, `arenahard_creative_writing` and `arenahard_math` hold the same questions as `arenahard` (253, 250 and 247 of its 750), so the probe keeps `arenahard` and drops the three. Then 19 benchmark folders hold all 20 performance-pool models (14,790 items), and 9 hold all 13 performance-cost models (12,066 items): `aime`, `arc-agi`, `arenahard`, `gpqa`, `hle`, `livecodebench`, `livemathbench`, `mmlupro` (3,000 items) and `simpleqa`. Across benchmarks a few questions recur, 1 to 7 per pair (for example 7 of `mathbench` in `mmlupro`). In the README's ten performance-cost benchmarks, `swe-bench` lacks `qwen/qwen3-235b-a22b-thinking-2507` and `tau2` lacks `openai/gpt-5-chat`
- Label: `score`, 0 or 1 from each benchmark's check, except 0.5 for some items of the four `arenahard` folders. The README names `hle`, `simpleqa` and `arenahard` as judged by a model; the others are answer or test checks. 4,326 `simpleqa` scores are null, none of them in the 13-model pool's files, and 1 `mbpp` score, which is why 973 of its 974 items count
- Cost and tokens: every record of the 13-model pool has `prompt_tokens`, `completion_tokens` and `cost`. Summed per model, the recorded `cost` is 0.853 to 1.502 times the README's price list applied to the same token counts (`openai/gpt-5` 0.926, `google/gemini-2.5-pro` 0.977), so, as with tau2-bench, the files do not say which price table produced it. 11 of the 20 performance-pool models record a nonzero cost and 9 record 0.0, so that pool fits `cost_blind` only
- Fit (in-sample probe, each task's best model chosen and scored on all its items; half is items // 2; shortfall is success minus the 0.95 Wilson lower bound at the half, as in routerbench-per-task.md, a yardstick for calibration noise, not a paired test of two models):
  - Performance pool: best single model `qwen/qwen3-8b`, success 0.6866. The per-task best is 7 different models over the 19 tasks. On 4 tasks another model leads by more than its shortfall, 3,467 items (0.234): `mbpp` (973 items, `qwen/qwen2.5-coder-7b-instruct` +0.213 at a shortfall of 0.039), `humaneval` (164, the same model, +0.152 at 0.095), `bbh` (1,080, `deepseek/deepseek-r1-0528-qwen3-8b`, +0.055 at 0.029) and `korbench` (1,250, `internlm/intern-s1-mini`, +0.042 at 0.038). Each task's own best model reaches 0.7168 (+0.0302), +0.0233 of it from those 4 tasks
  - Performance-cost pool: best single model `google/gemini-2.5-pro`, success 0.5990 at 732.99 USD recorded over the 12,066 items, ahead of `openai/gpt-5` (0.5984 at 382.88) by 0.0006; `qwen/qwen3-235b-a22b-2507` 0.5460 at 9.77. The per-task best is 3 different models over the 9 tasks. On 4 tasks another model, `openai/gpt-5` on each, leads by more than its shortfall, 3,733 items (0.309): `livemathbench` (121, +0.289 at 0.111), `arc-agi` (400, +0.093 at 0.069), `livecodebench` (1,055, +0.073 at 0.031) and `hle` (2,157, +0.046 at 0.025). Each task's own best model reaches 0.6240 (+0.0250), +0.0206 of it from those 4 tasks. With the two leaders 0.0006 apart, these leads are largely the two trading tasks, at half the cost for `openai/gpt-5`
  - Against RouterBench, where no eval has another model ahead by more than its shortfall and each eval's own best model adds 0.0002 (routerbench-per-task.md), both pools have tasks of that kind. Taken strictly, the yardstick of routerbench-per-task.md, about a fifth of the items in tasks with a margin of 0.05 and a half of 317 or more, holds 0.139 of the performance pool's items (`mbpp` and `bbh`) and 0.087 of the performance-cost pool's (`livecodebench`); the larger margins make up for it, as the in-sample gains of the lead tasks, 0.0233 and 0.0206, are about twice the 0.01 that yardstick aims at
  - The paper's README says the same of its own routers: "routing gains largely stem from capturing coarse-grained domain structure", read from its per-dataset oracle
- Converter: standard-library `tarfile` and `json`, reading members one at a time. Keep only (benchmark, split, model, `index`, `score`, `prompt_tokens`, `completion_tokens`, `cost`) and a digest of `origin_query` to check that an index names the same question for every model; never `origin_query`, `prompt`, `prediction`, `ground_truth` or `raw_output` themselves, whose questions and answers come from third-party benchmarks under their own terms

### Recommendation (2026-11-09)

- Take LLMRouterBench as the next routing evidence dataset: of the candidates it alone has a stated licence, several models' per-item outcomes on many tasks, a per-item cost and token counts, and tasks whose best model differs by more than the calibration noise
- Read the 13-model performance-cost pool as both flavors, with each record's `cost` as `cost_usd`; one routing task per benchmark. State five rules: `arenahard` or its three subset folders, never both, since they hold the same questions; which split each benchmark uses where it has two; an item is kept only where its question digest agrees across the pool; whether a 0.5 score counts as a success; and whether a benchmark that lacks a pool model (`swe-bench`, `tau2`) is dropped or routed without that model. The 20-model pool is a possible second, `cost_blind` reading
- What it does not fix: the models are from 2025, not those in `model_routing/data/models.json`; three of the nine full-pool tasks (`arenahard`, `hle` and `simpleqa`) are judged by a model; one run per item; the margins above are in sample, so only held-out halves will say how much of them a router keeps

## Seventh routing dataset (2026-11-11)

Question: since LLMRouterBench ([Many-task routing data (2026-11-09)](#many-task-routing-data-2026-11-09)), is there a public dataset, with a stated licence, that holds several models' per-item outcomes with a correctness label and would add a domain or a model generation that the six committed routing datasets lack?

Method: on 2026-11-11 the Hugging Face search API (`/api/datasets?search=<term>`, 100 results per term, most recently modified first) was queried for 22 terms: router, routing, RouterBench, RouterEval, LLMRouterBench, RouterArena, SPROUT, RoutingBench, model-routing, llm-routing, router-benchmark, MathArena, livebench, model_judgment, per-sample, model-outputs, leaderboard-results, evaluation-results, routellm, mix-instruct, helm and benchmark-results. They returned 1,051 distinct datasets, most of them router training sets, network or robot routing, or one model's evaluation logs. The shortlist below is those whose name or card suggests several models' per-item outcomes, plus the candidates of the 2026-11-09 section. For each, the dataset API (`?blobs=true`) gave the revision, the last-modified date, the licence field and the file sizes (summed below); the dataset viewer's `info` and `statistics` endpoints gave the columns, row counts and per-column counts; the GitHub API gave the licence and head commit of three code repositories. No dataset file was downloaded, and nothing from them is committed.

### Recommendation (2026-11-11)

- Take MathArena's final-answer competition outputs as the seventh routing dataset once the repository's owner accepts a committed results file derived from CC-BY-NC-SA-4.0 data. Of the candidates whose terms were read, it alone adds a model generation the committed evidence lacks (32 models from 2026, the same 32 in `aime_2026` and `hmmt_feb_2026`), an exact-answer label checked by a parser, and a recorded cost with the price pair that produced it
- If taken, the converter pins each set's revision and its parquet file's sha256, routes one task per competition over the models the chosen sets share, takes `cost` as `cost_usd` and checks it against the tokens times the row's price pair, and states four rules: which attempts become items, since attempt counts differ by model (on `aime_2026` 4 for 26 models, 2 for 5, and 96 rows for `Qwen3.5-4B`), for example only the attempt indexes every pooled model has; that the calibration and held-out halves split by `problem_idx`, so the attempts at one problem never straddle them; whether an attempt is kept whatever its `output_tokens`, since the files record no finish reason; and the ID mapping above
- If the NonCommercial terms are declined, the next candidate is, provisionally, the arXiv sets: CC-BY-SA-4.0 (ShareAlike without NonCommercial, so the ShareAlike part needs the same decision), the same fields and exact-answer label, and 47 questions in the October 2026 release, more than either competition, by five models, more than the four agents the committed tau2-bench evidence routes over. Before an E row, read each release's `model_config` values (the viewer's `statistics` endpoint failed on both releases tried and its `rows` endpoint rate-limited the probe) to learn which models they are and whether pooled releases share them
- Not assessed, so not ruled out: the four candidates whose licence field is `other` (terms not read) and the item-level scores of the Ukrainian router log (files not read)
- What it does not fix: 30 to 33 problems per competition, so calibration halves of 15 or 16 problems unless competitions are pooled, and attempts at one problem are not independent items
